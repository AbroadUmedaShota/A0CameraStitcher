# 通常画面からの補正条件確認（#357、#351 R3の最初の工程）

二台用WPF画面の「ファイル → 保存した補正条件を確認」から、保存した条件JSONを明示選択し、校正条件のファイル名、出力範囲、DPI、画素寸法、色補正の有無を確認できる。

利用できるのは起動時の履歴初期化が成功した後で、機体照合/Live開始前など、既存の履歴確認gateが許可する状態だけ。既存の排他予約を保持してwindowを開き、終了時に解放する。撮影中、Live中、機体照合後、Close未確認時や終了中に新しい操作を開始しない。現在のtransaction、reviewの採用状態、承認profileのgateは変更しない。

## 表示と読込

対象は #356 の `a0.saved-review-evaluation-conditions.v1`。固定local drive上の通常pathにある最大64 KiBの明示ファイルをread-onlyで読み、UNC・stream・曖昧なpathはファイルへアクセスする前に拒否する。objectの未知/重複/欠落欄、型、hash表記、整数表記と範囲、crop/DPI/ceil寸法、相対path表記を検査する。別のファイルの読込に失敗した場合、前回の設定表示を消し、未選択と読込失敗の案内へ戻す。

このreaderは保存内容の表示だけを担当する。参照先の原画像・profile・jobを開かず、実行プログラムも起動しない。表示には、開発評価用の設定で、元画像照合・補正評価・品質確認はまだ実行していないことを常時示す。保存ファイル内の文字列をコマンドや承認状態として扱わない。

## 検証と後続

`OperatorShellTests --saved-evaluation-conditions-window` は独立した人工条件、厳格な拒否、失敗時の表示消去、排他gate、実際のWPF controlへのbindingと画面描画を確認する。この検査を `Test-M3Simulated.ps1` へ追加し、既存の通常テスト数と失敗条件は維持する。ローカルでは #356 の実際の生成ファイルを引数として渡し、producer/consumerの互換性も確認する。

この工程はR3への着手であり、全撮影フローの完成ではない。条件と原画像の照合、補正評価の実行と結果表示、撮影→Merge→書き出しの通常UI接続、製品の承認/期限/実測対応のgate、実機/品質受入は後続に残す。
