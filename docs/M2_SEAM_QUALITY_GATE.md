## 0. 要約

- **ゲートの量**: 書き出す合成と同じ写像で A と B を別々に出力の格子へ置き（混ぜない）、遷移帯（A から B へ切り替わってよい範囲）の全域で、二枚の局所的な位置の差を出力の px で測る。合成後の画像は入力にしないので、seam-cut でも feather でも値は変わらない（#380）
- **判定**: 測れた全箇所の見えるズレの最大で判定する（D1）。中身の無い行は校正の予測ズレにその撮影で観測した予測の外れを足した値で補い、最大に入れる。測れた箇所が 1 つも無ければ不合格
- **最大で判定するための仕組み**: 1 点の誤照合で不合格にも合格にもならないよう、(1) 点の有効性を値の大小と無関係な検査（一意な最大、往復照合、周期の検査、点ごとの不確かさ）で決める、(2) 線を超えた点は条件を変えた 3 通りで測り直し、2 通り以上が一致した時だけ「確定した超過」にする、(3) 合格の根拠になる区画も同じく 2 つの一致を要求する、(4) 値が大きいという理由では点を捨てない。点ごとのノイズは σ 0.05 px 以下を目標にする。数千点の最大はノイズだけで約 4σ（0.2 px）持ち上がるので、その分をガードバンドとして所有者に諮る
- **配置の大域的な確認（#392）**: 局所の検査は、格子や周期模様の一周期分の配置のずれを見分けられない（周期が探索半径より大きい、または周期の検査の範囲 ±2R の外にある時）。測れた区画の中から、周期でない中身を持つ区画を「錨」として選び、広い半径（768 px）で探し直して局所の測定と同じ位置に一意な峰があることを確かめる。確かめられた錨が 4 区画に満たなければ不合格にする。合成の遷移帯がゲートの帯の外に出ていても不合格にする。設計は 16.11
- **浮き**: 二台の視差は基線の向き（A と B を結ぶ向き）にだけ出て、紙が浮く向きでは符号も決まる。許された相似を除いた残りが基線の向きに偏っていれば「浮き」と判別し、高さの目安と位置を出す。紙が約 0.3 mm 浮くと 1 px を超える見込み（※推定）
- **AF（D3）**: AF-S は撮影のたびにピントを合わせ直し、倍率が 0.1〜0.5% 変わる見込み（※推定）。帯ではこれが最大で約 3〜15 px のズレになる。A と B の相対の倍率の差は撮影ごとの相似（方針の上限内）でそのまま消せる。歪みのわずかな変化は残差としてゲートと局所合わせで扱う。保存 JPEG の MakerNote（読み取りのみ）と撮影ごとの相似の値を記録に残し、校正との食い違いの推移を追う。平置き校正にも置き方ごとの焦点距離の倍率を 1 自由度足す。中央に模様が無く合焦できない時は、撮影の前に案内し、拒否されたら理由と置き直し方を出す
- **精度の道筋**: 今の平置き校正の食い違い（#374）は最大で合格線の数倍ある。遷移帯を帯の中央に限る、重なりの置き方を二台で共有して同時推定する（置き方ごとの倍率つき）、撮り足しと紙の押さえ、撮影ごとの相似、と積み、最後に局所合わせ（D2）で最大 0.5 px 前後を狙う（※推定）
- **経路**: ゲートは純粋なライブラリにし、先に所有者が見ている未校正の開発経路へ入れる。未校正の経路は残差 8〜16 px なので構造上合格しない。合格を出せるのは校正済み（draft profile）の評価経路で、局所合わせもそこから入れる。製品経路へは #45 の承認 profile の後に #47 として移す
- **ライブの C**: 合否は撮影 JPEG だけで出す。ライブは直近の判定と位置の表示、大きな浮きの目安、合焦できそうにない時の案内だけを出し、「合格」とは書かない

## 3. ゲートの量

### 3.1 定義

- **配置した A と B**: 書き出す合成と同じ写像（未校正なら相似、校正済みなら profile の写像と撮影ごとの相似、局所合わせを入れたらその変形まで含めた最終の写像）で、A の原画像と B の原画像をそれぞれ出力の格子へ写した画像 P_A・P_B。混ぜず、明るさも合わせない
- **遷移帯 Ω**: 出力のうち、A から B への切り替えが起きてよい範囲。合成の方式はこの外で切り替えてはならない（不変条件 2）。今の feather は重なりの全幅、seam-cut は重なりから両端の余裕 64 px を除いた範囲に当たる。5.2 節の a で帯の中央に限る案を出す
- **ズレ d(p)**: Ω の中の点 p で、P_A の p に写っている紙の上の点が P_B で写っている位置から p を引いたベクトル。単位は出力の px
- **見えるズレ**: 内容が二方向に模様を持つ所では |d|。線が一方向だけの所では、線に直交する成分 |n·d|（n は線の法線）。横線が継ぎ目を横切る時に見える段違いは縦の成分だけで、線に沿った成分は目に見えない。線の端や交点は二方向の模様になり、そこで全成分を測る（この読み方は O2 で確認）
- **ゲートの統計**: 有効な全測定点（3.4 節で確定した点）の見えるズレと、中身の無い区画の予測値（3.5 節）を合わせた最大（D1）。p95・平均・最大の位置・2 番目の値・線を超えた点の数も記録するが、判定には最大だけを使う

### 3.2 合成方式に依存しない理由と、出力との結び付き

- ゲートは合成後の画像を入力にしない。入力は原画像 2 枚と、書き出す合成が使う写像関数と、Ω だけ。seam-cut が余白を選んでも、feather が帯の全体で混ぜても、P_A・P_B と Ω が同じなら値は同じ
- 書き出す合成とゲートが同じ幾何を見ていることは、報告で写像の hash（profile の fingerprint、撮影ごとの相似、局所合わせの制御点の値）を結んで示す
- Ω の外の出力の画素が P_A（左）・P_B（右）と一致すること（明るさの補正を戻した上で、丸めの範囲）を疎な標本で確かめる。合成の実装が Ω の外で B を混ぜていれば、ここで止まる

### 3.3 測り方

| 項目 | 案（設計定数、承認値ではない） | 理由 |
|---|---|---|
| 測定点 | Ω の中に 32 px（約 3.8 mm）おきの格子 | 紙のうねり（数 cm 規模）と校正の残差の変わり方より十分細かい。継ぎ目がどこを通っても、その近くに点がある |
| patch | 64 px 角（約 7.5 mm）。隣の点と半分ずつ重なる | 端数の詰めに足りる線の量を持ち、浮きの山（数 cm）を均さない大きさ |
| 区画 | 128 px 角（約 15 mm）。被覆の勘定の単位。継ぎ目に沿った 128 px の帯を「行」と呼ぶ | 1 区画に 4〜16 点が入る |
| 探索の半径 | 校正済み: ±16 px、未校正: ±48 px。端に当たったら多段で ±256 px まで広げる | 予想される残差より広く、周期模様の取り違えを減らすため狭い。冊子の浮き（数十 px、#374）は広い探索で拾い、不合格（浮き）として理由を出す |
| 標本 | 原画像を写像関数で patch ごとに直接標本化する（Catmull-Rom）。P_A・P_B の全体は作らない | 合成の補間（bilinear）の位相による偏りを測定に持ち込まない。メモリを使わない |
| 照合 | 輝度の勾配の強さの平均を引いた正規化相関（`zero_mean_correlation.hpp`）で整数の位置、#323 と同じ格子の半減で端数（7 段で 1/128 px） | 明るさの比（帯の中で 1.27 → 0.99、#362）に強い。曲線の当てはめを使わない今のやり方に揃える |
| 一方向の内容 | 構造テンソルの固有値の比で一方向と判定したら、法線の向きだけを 1 次元で探す | 開口問題。見えるズレだけを測る |

### 3.4 最大で判定するための、外れ値と不確かさの扱い

最大は 1 点で決まる。誤照合の 1 点が大きく出れば撮り直しが無駄に増え、小さく出た誤照合で区画が「測れた」ことになれば、本当のズレを見逃す。どちらも次の 4 つの仕組みで抑える。

**(1) 点の有効性は、値の大小と無関係な検査で決める**

1. 最大が厳密に一つ、探索の端に無い（#318 と同じ）
2. 往復照合: A → B と B → A の両方を測り、同じ整数位置に戻り、端数の差が 0.05 px 以下（案）
3. 模様: 二方向の点は構造テンソルの両方の固有値が 0 でない。一方向の点は法線の向きに模様がある
4. 周期の検査: A の patch の自己相関で、探索半径の 2 倍の内側に主峰の 0.8 倍（案）以上の副峰があれば、その向きでは無効。格子・ハッチング・点線・等間隔の文字で、一周期ずれた位置に合ってズレを小さく見せるのを防ぐ
5. 点ごとの不確かさ u_i: 往復の差と、相関の峰の鋭さ（峰の周りの曲率と画像のノイズの見積もり）から求め、G1・G6 で確かめた系統の下限を足す。u_i が 0.05 px（案）を超える点は無効
6. patch が A と B の両方の被覆の内側に収まる

**(2) 線を超えた点は、条件を変えて測り直して確定する**

- 見えるズレが「合格線 − ガードバンド」を超えた点は、条件を変えた 3 通り（patch を ±16 px ずらす、patch を 96 px にする、勾配でなく輝度の相関にする）で測り直す
- 2 通り以上が、元の値と max(3u_i, 0.1 px)（案）の内側で一致すれば「確定した超過」。最大に入れ、不合格の根拠にする
- 一致しなければ「未確認」。最大には入れないが、その区画を「測れた」にも数えない。未確認の点を 1 つでも持つ区画は、ほかに確定した点や一致する点があっても「中身があるのに測れない」にする（3.5 節。**#385 Q1 の所有者決定**）。未確認の点は位置と 3 通りの値を記録し、G1・G6 の改善の材料にする
- 本当の局所のズレ（折り目の山、貼った紙の端）は、ずらした patch や大きな patch にも同じ形で写るので確定する。誤照合はたいてい文脈を足すと消える

**(3) 合格の根拠になる区画にも同じ一致を求める**

- 中身のある区画を「測れた」に数えるのは、有効な点が 2 つ以上あって互いに max(3u, 0.1 px) の内側で一致する時か、1 点でも (2) と同じ測り直しで確定した時だけ。ただし未確認の点を 1 つでも持つ区画は、この条件を満たしていても「測れた」にしない（#385 Q1 の所有者決定）
- 隣の区画の値と、紙の曲がりで説明できないほど食い違う区画（案: 区画の間隔あたり 0.5 px 超）は「測れた」に数えない。その点の値は最大に残す

**(4) 値が大きいという理由では点を捨てない**

- 外れ値を除く処理（中央値からの距離で落とす等）は入れない。最大を下げる向きに働くので、本当の局所のズレを隠す
- 有効か無効か、確定か未確認かは、すべて値の大きさと無関係な条件（一意性・往復・周期・不確かさ・測り直しの一致）で決まる。測り直しを始める条件だけが値に依存するが、確定の判断は一致だけで行う

**不確かさと合格線**

- ノイズだけでも、数千点の最大は 1 点の σ の約 4 倍持ち上がる（4000 点の正規分布の最大の期待値は約 3.9σ）。1 点の σ を 0.05 px 以下に抑えれば、この持ち上がりは 0.2 px 程度に収まる。G1 の目標を「1 点の誤差 0.2 px 以下」ではなく「1 点の σ 0.05 px 以下、系統の偏り 0.05 px 以下」に置く
- 合格を「測った最大 ≤ 1 px」にすると、本当の最大が 1 px ちょうどの時に約半分が合格になる。「測った最大 + U ≤ 1 px」（U はガードバンド、推奨 0.2 px）にすれば、合格した書き出しの本当の最大が 1 px 以下であることを、確かめた不確かさの範囲で言える。U を置くかは O1
- 逆に、本当の最大が 0.8 px 前後の撮影では、ノイズで最大が 1 px 近くまで上がり不合格が増える。この率は G6 の実写の繰り返し撮影で測り、所有者に出す

### 3.5 測れない所の扱い

区画ごとに次のどれかに分ける。

| 区画の種類 | 条件 | ゲートの値 |
|---|---|---|
| 測れた | 中身があり、3.4 節の (3) を満たす | 確定した点の見えるズレ |
| 中身なし | P_A にも P_B にも中身が無い（勾配の量がノイズの数倍未満、案） | 校正の予測ズレ + その撮影の予測の外れ（下記）。最大に入れる（D1） |
| 中身があるのに測れない | 中身があるが (3) を満たさない（周期・薄い線・片方にだけ写る）、または未確認の点を持つ（ほかの点がどうであっても。#385 Q1 の所有者決定） | 値を持たない。1 区画でもあれば不合格（`failed-unmeasurable`）。許容を置くかは O3 |

- 中身の検出の線は、有効な点の条件より低く置く。薄い線は「中身があるのに測れない」になり、書き出さない側に倒れる
- **中身なしの区画の予測**（D1）:
  - 校正の予測ズレ p(x): 校正の撮影（G8）で、遷移帯を覆うように置いたチャートの節点から測った A/B の食い違いを、遷移帯の位置の関数として持つ（draft の校正報告に「遷移帯の予測ズレ地図」として出す。profile は変えない）
  - 予測の外れ m: その撮影の測れた点で、測った値と予測の差の最大。AF の倍率差や紙のうねりで予測が外れている分を、その撮影ごとに見積もる
  - 中身なしの区画の値は |p(x)| + m（同じ補正・局所合わせの後の値どうしで比べる）。保守的な見積もりで、予測の外れが大きい撮影では中身なしの行でも不合格になりうる
  - 予測地図が無い（未校正の経路、校正の範囲の外）区画は値を作れないので、不合格（`failed-unmeasurable`、理由は「予測が無い」）。※所有者確認 O3
- 測れた区画が 1 つも無ければ不合格（D1）
- 直し方の案内: 「継ぎ目の上の、細かい繰り返し模様（または薄い線）の所で位置を測れませんでした。紙を左右に数 cm ずらして撮り直してください」。図面を動かせば継ぎ目に来る中身が変わる

### 3.6 判定

方針（開発経路は方針ファイル、製品は profile の `qualityContract`）の値だけを使い、コードに既定値を置かない。

1. 入力・幾何・方針が欠けていれば `not-run`。撮影ごとの補正が上限を超えて合成できない時（ADR-0021 の `physical-adjustment-required`）もここで、その理由と案内をそのまま出す
2. 測る（局所合わせを使う時は 5.5 節の手順で、前と後の両方）
3. 浮きの判別（4 節）を、局所合わせの前の量で行う
4. 確定した点の最大 + U が合格線 L を超えれば不合格。浮きと判別されていれば `failed-lift`、ほかは `failed-displacement`
5. 測れた区画が 0、または中身があるのに測れない区画が許容を超えれば `failed-unmeasurable`。未確認の点を持つ区画は「中身があるのに測れない」に数える（#385 Q1 の所有者決定）
6. 中身なしの区画の予測値 + U が L を超えれば `failed-displacement`（理由は「予測による」）
7. 配置が大域的に確かめられなければ不合格（広い半径の確認で別の位置に強い一致があれば `global-placement-mismatch`、確かめられた区画が足りなければ `global-placement-unverified`）。合成の遷移帯がゲートの帯の外に出ていれば `transition-outside-band`、遷移帯が渡されていなければ判定不能（16.11）
8. どれにも当たらなければ `passed`

- L = 1 px は所有者の決定。U は O1
- `passed` は継ぎ目のズレについての判定だけで、品質の合格ではない。#47 のほかの項目と合わせて初めて書き出せる
- 上限と等しい値は通す（今のリポの約束に揃える）

### 3.7 測定精度の見込みと確かめ方

- ノイズによる誤差: 線が数本入った 64 px 角の patch では、Cramér–Rao の下限で 0.01 px 以下の見込み（※推定）。支配するのは系統誤差
- 系統誤差の候補: 補間の位相による偏り、JPEG のブロック、A と B のぼけ方の違い（帯はどちらのカメラでも画面の端）、倍率色収差（端で色ごとに位置がずれる）、照明の反射の違い。どれも 0.05 px 以下に抑えられる見込みだが ※推定 で、次の 3 段で確かめる
  1. 人工画像（G1）: 既知のズレの場（一定、線形、半径方向の歪み型、倍率の差、局所の山）を、図面風・文字・ハッチング・無地・薄い線の中身に入れ、明るさの傾き（1.27 → 0.99）、ぼけの差、ノイズ、JPEG を加えて、1 点の σ ≤ 0.05 px・偏り ≤ 0.05 px・最大の誤差 ≤ 0.2 px を確かめる。周期模様で一周期ずれた合致が確定しないこと、誤照合を混ぜた時に未確認になることも確かめる。生成器はゲートのコードにリンクしない（#275 と同じ隔離）
  2. ゼロ試験（G6、実機）: 同じカメラで動かさずに 2 回撮った画像どうし、1 枚の画像とそれを既知の端数だけ動かした画像で測る。AF-S では撮影ごとにピントが合わせ直されるので、同じカメラの 2 回の差には倍率の差も入る。相似を除いた後の値で見る
  3. 独立な検証点（G6、実機。#385 の完了条件）: 基準点のチャートを遷移帯の上に平らに置いて撮り、P_A と P_B の上の基準点の位置を #275 の評価器（別のコード）で測った差と、ゲートのその位置の値を比べる。差が 0.2 px 以下であること
- 色収差は輝度で測る値に入る。色ごとのずれを判定に含めるかは O9

### 3.8 比べた測り方

| 観点 | A: 合成後の画像で測る | B: 原画像どうしの対応点を写像で出力に移す | C: 配置した A と B を patch ごとに標本化して測る（推奨） | D: チャートの基準点で測る |
|---|---|---|---|---|
| 合成方式への依存 | 依存する。seam-cut は残差を見えなくする（#380） | しない | しない | しない |
| 開発速度 | 速いが目的を満たさない | 遅い。出力 → 原画像の逆（歪みの逆）が要る（#317 にはある） | 中。#318・#323 の部品と `OutputToCamera` をそのまま使える | 速いが図面では使えない |
| 運用コスト | 低い | 中 | 中。撮影ごとに数秒（※推定、G1 で測る） | 撮影ごとにチャートが要る |
| 精度 | 継ぎ目が余白を通ると測れない（F9） | 高い | 高い。#323 で 0.025 px の実績（人工） | 最も高いが点が疎 |
| 既存スタックとの親和性 | 中 | 中 | 高い。製品の renderer と同じ写像関数 | 高い（#275） |
| 採否 | 採らない | 採らない（C と同じ量を、逆写像の手間をかけて測ることになる） | 採る | ゲートの検証にだけ使う（3.7 節の 3） |

## 4. 浮きの検出

### 4.1 物理

二台のカメラの真下の点を C_A・C_B、カメラの高さを H とする。台から高さ h だけ浮いた紙の上の点は、A の画像では C_A から離れる向きに、B の画像では C_B から離れる向きにずれる。A と B の差は

  d_parallax = h / (H − h) × (C_B − C_A)

で、**点の位置によらず基線の向きを向き**、紙が台より上にある限り符号も一つに決まる。大きさは高さに比例する。#374 の逆算の比では、紙が約 0.3 mm 浮くと 1 px を超える（※推定、PM の見積もりと同じ）。紙が全体として一様に持ち上がった場合（板の上など）は一様な平行移動と倍率になり、撮影ごとの相似で消える。残るのは面からの曲がりだけ。

### 4.2 判別の手順（校正済みの経路）

1. 局所合わせの前の確定した点で、ズレの場に相似を頑健に当てはめる（#365 と同じ最小メディアン法と再当てはめ）。相似が撮影ごとの上限の内側なら除いた残り r、外なら除かない
2. r を基線の向きの成分 r_e と直交する成分 r_⊥ に分ける。基線の向きは、G8 で「図面と同じ置き方で、既知の高さだけ持ち上げたチャート」（#374 の次の撮影 2）を撮って実測する。それまでは配置の向き（左右なら出力の x）で代える
3. 合格線を超えた確定した点のうち、|r_e| が |r_⊥| の 3 倍以上（案）の点が大半（9 割以上、案）を占めれば `failed-lift`。超えた点の r_e の符号が「浮き」の向きにそろっている割合と、高さの目安 h ≈ |r_e| ÷（px/mm の比）を記録する
4. それ以外の不合格は `failed-displacement`。r が相似でよく説明できる（当てはめの残差が小さい）なら「カメラが校正の時から動いた」、画面の端に偏るなら「校正の範囲の外」と、理由を細かく分けて記録する

### 4.3 案内

| 判定 | 表示（案） | 直し方 |
|---|---|---|
| `failed-lift` | 「紙が台から浮いています。継ぎ目の上から約 Y mm の所で、高さ約 Z mm です（目安）」 | 紙を平らにして撮り直す（四辺を留める、押さえる）。綴じた冊子など平らにできない図面は書き出せません |
| `failed-displacement`（相似で説明できる） | 「継ぎ目で最大 X px ずれています。カメラが校正の時から動いた可能性があります」 | 撮り直し。直らなければ校正のやり直し |
| `failed-displacement`（端・局所） | 「継ぎ目の Y の辺りで最大 X px ずれています」 | 撮り直し。同じ所で続けば校正の撮り足し |
| `failed-displacement`（予測による） | 「継ぎ目の中身の無い所で、校正からの予測が基準を超えました」 | 撮り直し。続けば校正のやり直し |
| `failed-unmeasurable` | 3.5 節 | 紙をずらして撮り直し |

### 4.4 限界

- 未校正の経路では、レンズの歪みの残差（8〜16 px）が帯の中ほどで基線の向きに近い向きを持つので、浮きと見分けにくい。未校正では「浮きか、校正していないことによるずれ」と両方を案内し、`failed-lift` を断定しない
- 校正の残差が合格線に近い間は、帯の高さの中ほどで同じ紛らわしさが残る。G7・G8 で校正の残差を下げるほど判別がはっきりする
- 机のくぼみ（紙が台より下）は符号が逆になる。符号の割合は記録だけにして、判別の条件にはしない

## 5. 精度を 1 px 以下に上げる道筋

### 5.1 誤差の内訳

| 源 | 今の見立て | 1 px に効く目安 |
|---|---|---|
| 校正のモデルと範囲（外挿、5 係数の揺れ） | 最大は帯の端の校正範囲の外（F3） | 範囲を覆えば下がる |
| 二台の結び付き（共有する置き方が 1 つ） | 帯の上下の端で A と B の関係が直接は拘束されていない（F4） | 同時推定で下がる |
| AF による置き方ごとの倍率の差（校正の撮影の中） | 校正は AF-S で撮り（F5）、モデルに置き方ごとの倍率が無い（F4）。倍率の差が 5 係数と残差に漏れている疑い（※推定） | 置き方ごとの倍率の自由度で下がる |
| AF による撮影ごとの倍率の差 | 0.1〜0.5%（※推定）。帯の中心から約 3000 px の所で最大 3〜15 px | 撮影ごとの相似で消える（6 節） |
| 紙と机の平らさ（チャートも図面も） | 5 係数が平らさの差を吸っている疑い（F3、※推定） | 約 0.3 mm の浮きで 1 px（※推定） |
| リグの動き | 未測定 | 撮影ごとの相似で消える |
| 測定（ゲート自身） | 3.7 節 | 1 点の σ 0.05 px |

### 5.2 手段

**a. 遷移帯を帯の中央に限る（ソフト、撮影なし）**
重なりは幅の約半分（#367）あり、切り替えに全幅は要らない。Ω を帯の中央に限れば、校正の範囲の外になりやすい両カメラの端がゲートの範囲から外れる。最大が出ていた CAM-B の端（F3）はここで外れる。Ω の幅は G0 で既存の実測を帯の位置ごとに集計し直してから決める（O4）。

**b. 重なりに置いた置き方を二台で共有して同時に推定し、置き方ごとの倍率を足す（ソフト）**
- 平置き校正の推定器は、帯の上端・下端の回も置き方をカメラごとに別に解く（F4）。両台に写った置き方は (θ, t) を二台で 1 組にし、二台の LM を一つにする。帯の上・中・下で A と B の関係が直接拘束され、継ぎ目の食い違いそのものが最小化の対象になる
- AF-S では校正の置き方ごとにピントが合わせ直され、倍率が変わる。カメラごと・置き方ごとに公称の焦点距離に掛ける倍率 (1 + ε_cj) を 1 自由度足す（主点のまわりの拡大で、AF の倍率の変化の形に合う）。重なりの置き方では ε を 0 に固め、文書の座標の尺度を決める
- job に「両台で共有する置き方」の欄を足し、報告に置き方ごとの ε と、撮影時の MakerNote の焦点の記録（6.2 節）を並べる。既存の撮影（帯の上端・下端・重なりの 3 回）にもそのまま当てられる

**c. 撮り足しと紙の押さえ（実機、所有者の GO の後）**
- 帯に沿って上端・上寄り・中央・下寄り・下端の 5 か所に、両台に写る置き方を各 2 回（少しずらして）。A の帯側の縁と B の帯側の縁（#374 の次の撮影 1）を含める。これが中身なしの行の予測地図（3.5 節）の元になる
- 既知の高さだけ持ち上げた置き方を 1 回（#374 の次の撮影 2）。基線の向きと、高さと px の比を実測する（4.2 節）
- AF-S のまま撮る（D3）。両台の中央に模様が来るよう、2 枚目のチャートか図面を置いて合焦を通す（6.4 節）
- チャートも図面も、同じ押さえ方で平らにする（O5）。ガラス板で押さえる場合は、校正も撮影も同じ板の下で行う（板の屈折は面の持ち上がりと同じに働き、同じ条件なら写像に入る、※推定。ただしガラスの上で AF が合うかは ※要確認）
- 置き直しの再現性を見る: 同じ所に 2 回置いて、残差の形が同じなら机・レンズ（固定の成分）、違えば紙のうねり（その都度の成分）。どちらが効いているかで e と f の比重が決まる
- 組数は 12 前後で、ADR-0033 の較正用の枠（12 組）の残りを超える見込み。所有者の判断が要る（O6）

**d. 撮影ごとの相似を校正基準で（ソフト）**
校正済みの写像に、撮影ごとに上限つきの相似（#316〜#325）を足す。AF の倍率差とリグの小さな動きを消す。局所の誤差は減らさない。上限は今の方針ファイルの値（回転 2°・倍率 1%）を流用しない（#362 の横断レビューのとおり、取り付けの許容と撮影ごとの許容は別物）。倍率の上限は AF の倍率差（※推定 0.1〜0.5%）を収める値が要る（O10）。

**e. 校正の残差地図を固定の補正として持つ（検討案、ADR-0034 の欄の追加が要る）**
c の撮影で測る遷移帯の予測ズレ地図を、予測（3.5 節）にだけ使うのでなく、固定の補正として profile に持たせる案。机の平らさとレンズのモデルの足りない分（毎回同じ成分）を消す。撮影ごとに推定しないので ADR-0021 には触れない。チャートのうねりを地図に焼き込む危険があり、c の再現性の確認で固定の成分が支配的と分かった時だけ採る。

**f. 遷移帯の中だけの局所合わせ（D2、ADR 改定）**
撮影ごとに、その撮影の A と B から帯の中の滑らかで小さな変形を求めて当てる。紙のうねりと、AF による歪みのわずかな変化（相似で消えない分）を吸う。5.5・5.6 節。

| + d 撮影ごとの相似 | 同上 | 同上 | 同上 | AF の倍率差（最大 3〜15 px）とリグの動きを消し、平らな日の値を保つ。d が無いと AF のたびにこの行より悪くなる |
| + f 局所合わせ（e を併用すれば上限を小さくできる） | 約 0.15 | 約 0.3 | 約 0.5 | 検証点（当てはめに使わない点）での値。測定の誤差と、制御点の間隔より細かい変わり方が残る |

読み方: f が無いと、ガードバンド込みの 0.8 px を実際の紙で安定して下回るのは難しい見込み。d は AF を前提にすると必須。a〜d を先に進めて f の上限を小さく保つ（上限が小さいほど、浮きや校正の崩れを隠す余地が減る）。

### 5.4 未校正の経路の扱い

未校正の経路（相似だけ）は残差 8〜16 px で、局所合わせで吸うには 16 px 規模の変形が要る。これは自由な変形と変わらないので、未校正の経路には局所合わせを入れない。中身なしの行の予測地図も無い。未校正の経路のゲートは常に不合格を正直に出す役にとどめ、合格を見るには校正済みの経路を使う（7 節）。

### 5.5 局所合わせの設計

- 範囲: Ω の中だけ。Ω の境で 0 に戻す（境の手前の数百 px で滑らかに減らす）。Ω の外の写像は profile と撮影ごとの相似のまま
- 自由度: 継ぎ目に沿って間隔 K px（案 256 px、約 30 mm）、帯を横切る向きに 3 列の制御点に、2 成分のずれを持たせ、3 次の B-spline でつなぐ。約 7000 px の高さで 30 行 × 3 列 × 2 成分 ≒ 180 自由度（※推定）
- 当て方: 変形を A と B に半分ずつ逆向きに当てる案と、B だけに当てる案がある。半分ずつなら各画像の歪みが半分になる。今の約束（明るさは B だけ、A が基準）との整合を含めて O7
- 推定: 局所合わせの前の確定した点を、区画の市松模様で「当てはめ用」と「検証用」に分ける。当てはめ用の点だけで制御点を最小二乗で求める（滑らかさの正則化つき、乱数なし）。中身なしの区画の制御点は正則化で隣から決まる
- 上限: 変形の大きさの最大 D px と、ひずみ（変形の勾配）の最大 s。局所合わせの前の量が、中身のある区画のどこかで D を超えるなら当てない。上限で切って部分的に当てることはしない
- ゲート: 局所合わせの後の量は検証用の点だけで測る（D2）。検証用の点も 3.4 節の確定の手順を通す。前の量と後の量の両方を報告に残す。浮きの判別は前の量で行う（4.2 節）
- 記録: 制御点の値、分け方、当てはめの残差、上限の値を報告に書き、原画像と報告から合成を作り直せるようにする

### 5.6 ADR 草案の要点（ADR-0021 の改定、D2 で方針は承認済み）

- 題: 継ぎ目の遷移帯に限った、上限つきの局所合わせを撮影ごとに認める
- 状態: Proposed。所有者は方針を認めた（D2）。範囲と上限の値は所有者決定欄に残し、G8 の撮影結果を添えて改めて確認する（O7）
- 改定する文: ADR-0021 の安全境界に「承認済み profile の写像の上で、遷移帯の中だけ、上限つきの滑らかな局所合わせを撮影ごとに一時的に当ててよい。これは自由な homography でも profile の学習でもない」を足す。ADR-0034 の不変条件 2（撮影ごとの補正は相似に限る）に同じ例外を足す
- 範囲: 遷移帯 Ω の中だけ。Ω の外は変えない。校正済みの写像（製品は approved、評価・開発は ADR-0033 4 節の範囲の draft）の上だけで、未校正の経路では使わない。ライブの C には当てない（C は frame から推定しない、ADR-0036）
- 上限: 変形の最大 D px とひずみの最大 s を所有者が決め、製品では profile の `correctionEnvelope` の新しい欄に置く（ADR-0034 の欄の追加）。上限を超える場合は当てず、clamp しない
- 自由度: 継ぎ目に沿った粗い制御点の 2 成分のずれ（5.5 節）。全体の変換は持たない
- 学習しない: その撮影の A と B だけから求め、次の撮影に持ち越さない。profile に書かない。校正（#45）の入力に自動では使わない
- ゲートとの関係: 局所合わせに使った点でゲートを測らない。前の量と後の量を両方残す。浮きの判別は前の量で行い、D を超える浮きは局所合わせで消さず `failed-lift` にする。D は「平らな一枚ものの小さなうねり」と「浮き」の境を決める値になる
- 危険と抑え: 校正の崩れや浮きを隠す → 上限、検証用の点、前の量の記録、浮きの判別を先に行う順。図面の寸法を局所で変える → ひずみの上限 s

## 6. AF（AF-S）を前提にした扱い（D3）

### 6.1 倍率と歪みの変化

- AF-S はシャッターの前にピントを合わせ直す。合う位置が撮影ごとに数 mm 違うと、倍率が 0.1〜0.5% 変わる見込み（※推定）。倍率の変化はおおむね各カメラの主点のまわりの拡大で、文書の面の上では拡大と平行移動、つまり相似になる
- A と B の相対の倍率の差 ε は、帯で ε ×（各カメラの中心からの距離）のズレになる。中心から帯の遠い隅まで約 3000 px（※推定）なので、0.1% で約 3 px、0.5% で約 15 px。合格線の何倍にもなるので、撮影ごとの相似（5.2 節の d）は AF を前提にすると省けない
- 撮影ごとの相似は B を A に対して合わせる。A 自身の倍率の変化は出力全体の実寸（DPI）の誤差として残るが、継ぎ目のズレには出ない。実寸は #47 の別の項目で扱う
- 倍率の差が方針の上限（O10）を超えたら合成しない。理由は「A と B の写る大きさの差が上限を超えました（ピントの合い方の差）」、直し方は撮り直し。撮り直すとピントも合わせ直される
- 歪みのわずかな変化（ピントの位置で係数が少し変わる分）は相似で消えない。小さい見込み（※推定）で、ゲートの残差と局所合わせで扱い、6.3 節の推移で監視する
- ピントが図面の面以外（紙の上の重し、定規など）に合うと、倍率が大きく変わる。相似の上限で止まるか、残差としてゲートに出る

### 6.2 AF の合わせ直しの検知と記録（読み取りだけ）

カメラへの新しい命令と設定の書き込みは増やさない。使うのは、保存 JPEG と既存の読み取りの診断だけ。

| 記録する項目 | 出どころ | 用途 |
|---|---|---|
| フォーカスモード、AF エリア、合焦した AF 点 | 保存 JPEG の MakerNote（F17）、既存の読み取りの診断（F16） | 撮影の条件の記録。AF-S でない撮影を見つける |
| 焦点の距離の記録（レンズの情報） | 保存 JPEG の MakerNote（D810 と手元のレンズで記録され、使える細かさかは ※要確認） | 撮影ごとと校正の時の比較 |
| A と B の相対の倍率・回転・平行移動 | 撮影ごとの相似の推定値 | 画像からの合わせ直しの量。MakerNote が粗くても使える |
| 予測の外れ m、局所合わせの前の最大・p95、局所合わせの量 | ゲートの記録 | 校正との食い違いの推移 |
| 合焦の拒否の有無と理由 | 既存の拒否の検出（F16） | 6.4 節 |

- 「合わせ直しを検知した」は、MakerNote の焦点の記録か画像から求めた相対の倍率が、前の撮影または校正の時と違うこととして記録する。どちらで検知したかも残す
- 校正の撮影の MakerNote の値も、校正の報告に置き方ごとに記録する（5.2 節の b の ε と並べる）。校正の時のピントの状態が撮影の基準になる
- 記録は撮影ごとの報告と、カメラ登録と同じローカルのフォルダの追記型の履歴（1 行 1 撮影、`a0.seam-gate-history.v1`、名前は案）に残す。公開しない

### 6.3 校正との食い違いの推移

- 履歴から、直近の撮影の (1) 相対の倍率、(2) 予測の外れ m、(3) 局所合わせの前の最大、(4) 局所合わせの量を並べ、StillReview と開発用の診断に出す
- 倍率の差と MakerNote の焦点の記録の差を並べて、倍率の変化が AF で説明できるかを見る。説明できない倍率の差（焦点の記録が同じなのに倍率が違う）はリグの高さの変化を疑う
- (2)〜(4) が撮影を重ねて増える、または倍率の差が上限の近くに張り付くなら「校正の時とピントか高さが違う。校正のやり直しを勧めます」と案内する。案内を出す条件の値は所有者が決める（O11）。決まるまでは並べて表示するだけ
- 推移は案内と診断にだけ使う。profile を更新せず、次の撮影の補正の初期値以外には使わない（ADR-0021）

### 6.4 合焦の確認で撮影が拒まれる経路

AF-S は合焦しないとシャッターを切らない。AF 点（今は画面の中央、※要確認）に線や文字が無い白紙だと拒まれる（F5）。

- 撮影の前（案内だけ）: ライブの縮小画像で、各カメラの AF 点の付近に模様があるかを見る。無ければ「右側（左側）の中央付近に線や文字が無いため、ピントが合わず撮影が止まる可能性があります。図面を少しずらすか、中央付近に模様が来るように置いてください」と出す。AF 点の位置を C の上に印で示す（表示だけ）。撮影は止めない
- 拒まれた時: 既存の検出（F16）の理由をそのまま出し、上と同じ直し方を出す。自動の AF のかけ直しやシャッターの再送はしない（#343・ADR-0006）。シャッター 0 の組は ADR-0032・ADR-0033 の数え方のとおり。片側だけ撮れた組は合成せず、原画像は残す
- AF 点を変える（カメラの操作で中央以外の点を選ぶ）運用は、人がカメラで行う設定の変更になる。撮影直前の設定の照合（ADR-0024）に AF 点が含まれるかは ※要確認。含まれるなら、AF 点を変える運用は所有者の判断が要る
- 合焦のための目印を図面の上に置く運用は採らない。目印が成果物に写るため

### 6.5 既存の決定との関係

- ADR-0033 6 節「2 台とも MF」と、校正の手順書の「MF、ピントリングを固定」は D3 で改める。改定の文面は G14 で出す
- 撮影直前に承認済みの capture profile と設定の一致を確かめる（ADR-0024）。フォーカスモードが照合の対象なら、AF-S の capture profile の承認が要る（※要確認）

## 7. 開発経路と製品経路

| 経路 | 幾何 | ゲート | 局所合わせ | 位置付け |
|---|---|---|---|---|
| 未校正の開発経路（WpdDualPreview の両台撮影 → 仮 Merge 保存、StillReview の再 Merge） | 相似（#365） | 入れる（G4）。構造上ほぼ常に不合格 | 入れない（5.4 節） | 所有者が見ている出力。正直な値を見せる |
| 校正済みの開発・評価経路（StitchEval + draft profile、StillReview からの #352 の橋渡し、G9 で両台撮影からも選べるようにする） | draft profile + 撮影ごとの相似 | 入れる（G3） | 先にここへ（G11） | 合格を出せる経路。改善の効果を測る所 |
| 製品経路（approved profile、`RenderDocumentPair`、M2 の書き出し） | approved profile + 撮影ごとの相似 | #47 として入れる（G13） | ADR が Accepted になり、上限が profile に入ってから | #45 の後 |

順番の推奨:

1. ゲートの測定と判定を純粋なライブラリにする（G1・G2）。経路に依存しない（写像関数を受ける）
2. 未校正の開発経路に入れる（G4）。所有者が見ている出力が「書き出さない」「最大 X px」を正直に出す。ただし不合格の合成を診断用に残すかを先に決める（O8）。全部止めると開発の確認ができなくなる
3. 評価経路に入れる（G3）。校正の改善（G7・G8）の効果をゲートの量で測る
4. 校正済みの合成を、所有者の見る開発の流れ（両台撮影の後）から選べるようにする（G9）。評価専用の入口（ADR-0033 4 節、既定 OFF のビルド）の範囲で行い、製品の配布物に入れない
5. 局所合わせを評価経路から入れ（G11）、同じ写像関数を通るので校正済みの開発経路にもそのまま効く
6. 製品経路へは、ゲートを #47 の枠（manifest、書き出しの公開点 ADR-0026）に入れ、局所合わせは ADR と profile の欄が揃ってから移す（G13）

## 8. ライブ映像の C

- 合否は撮影 JPEG だけで出す。ライブの縮小（長辺 640 px、撮影の約 1/11.5）では出力 1 px が約 0.09 ライブ px で、測れない。ライブには「合格」「基準内」と書かない
- 撮影の後: C の見出しに直近の判定（基準内／書き出さない理由）と最大のズレの値を出し、最大の位置と測れなかった区画を C の上に重ね表示する（表示だけで画素は変えない）
- 撮影の前（案内だけ）: (1) ゲートの測定器を縮小のまま当て、基線の向きのズレが大きい時に「紙が浮いているかもしれません。平らにしてから撮影してください」と出す。ライブで分かるのは出力で 6 px 程度（浮き約 2 mm）より大きい浮きだけ（※推定）。冊子の浮きは見つかるが、一枚もののうねりは撮影後まで分からない。(2) AF 点の付近に模様が無い時の案内（6.4 節）
- ライブの案内で撮影を止めない。frame ごとには測らず、ボタンか一定の間隔で測る
- 製品の C（ADR-0036）は「補正の推定の入力にしない」。案内は補正ではないが、frame から推定することには変わりないので、製品の C に入れるかは ADR-0036 の承認の時に確かめる（※要確認）。開発用の C（WpdDualPreview）では、今の自動位置合わせと同じ扱いで入れられる

## 10. 守る不変条件

1. ゲートは合成後の画像を入力にしない。入力は原画像、書き出す合成と同じ写像関数、遷移帯だけ。合成の方式を変えても判定は変わらない
2. 合成は遷移帯の外で A と B を混ぜない。遷移帯の外の出力が P_A・P_B と一致することを確かめる
3. 判定は確定した点と予測値の最大で行う（D1）。値が大きいという理由で点を捨てない。点の有効・確定は値の大きさと無関係な条件で決める
4. 中身があるのに測れない区画を基準内に数えない。測れた区画が 0 なら不合格
5. 合格線・ガードバンド・測れない所の許容・撮影ごとの補正の上限・局所合わせの上限・推移の案内の条件は、所有者の値を方針ファイルか profile から読む。コードに既定値を置かない。設計定数は報告に記録し、判定の線に流用しない
6. `passed` 以外は書き出さない（製品）。開発経路で診断用に残す場合も、成果物と区別できる名前と場所にする（O8）
7. 局所合わせに使った点でゲートを測らない。前の量と後の量を両方記録する
8. 浮きの判別は局所合わせの前の量で行う。上限を超える変形をしない（clamp しない）
9. ゲート・局所合わせ・推移の結果で profile を学習・更新しない。次の撮影に持ち越さない
10. 乱数を使わない。同じ入力からは同じ結果を出す
11. ライブの frame で合否を出さない。ライブの案内で撮影を止めない
12. 撮影ごとの補正の上限は、未校正の取り付けの許容（方針ファイルの 2°・1%）を流用しない
13. カメラへの新しい命令と設定の書き込みを足さない。AF の記録は保存 JPEG と既存の読み取りの診断から取る。合焦の拒否で自動の AF・シャッターの再送をしない

## 11. 実装ガイドライン

- 置き場所: `a0_m2_seam_gate`（名前は案）を `src/m2` に置く。STL と `a0_m2_render` の型だけに依存し、カメラ・ファイル・時計に依存しない。phase0 から使えるが m2 から phase0 を参照しない（今の向きを保つ）
- 入力: 原画像 2 枚（`BgrImage`）、A と B の `OutputToCamera`、遷移帯（出力の行ごとの [x0, x1)）、基線の向き（任意、無ければ配置の向き）、予測ズレ地図（任意、無ければ中身なしの区画は値を作れない）、設計定数（全引数必須）、点の分け方（全部／当てはめ用と検証用）。出力: 測定点、区画、統計、浮きの判別の材料
- 判定は別の純粋関数（`DecideSeamGate`、名前は案）にし、方針を受けて状態と理由を返す
- 測り直し（3.4 節の (2)）は測定器の中で行い、3 通りの値を点の記録に残す。測り直しの対象は「線 − ガードバンド」を超えた点と、区画を「測れた」にするために要る点だけにして、時間を抑える
- 共有: 相関は `zero_mean_correlation.hpp`、構造テンソルと往復照合は `image_patch_detail.hpp`・`overlap_estimation_detail.hpp` の関数を共有する。写して二つにしない。#323 の細探索は「全 seed 必須」の契約から切り離した点ごとの関数として取り出し、#318〜#323 の既存試験の出力が変わらないことを確かめる
- 写像関数は renderer と同じものを渡す（未校正は相似から、校正済みは profile と撮影ごとの相似から作る）。局所合わせは写像関数に足す形にし、renderer にも同じ関数を渡す
- MakerNote の読み取りは保存 JPEG を開く既存の層に置き、ゲートのライブラリには値だけを渡す
- 時間: 7360 幅の撮影で数千点と測り直し。Release で数秒の見込み（※推定）。両台撮影の 180 秒の期限の中で、合成の後に測る。G1 で測って記録する（16 節）
- 試験: 生成器はゲートにリンクしない（リンク隔離の検査に足す）。seam-cut と feather で同じ判定になることを試験に入れる（#380）

10. 局所合わせを A と B に半分ずつ当てる場合の、「A が基準」という今の約束との整合

12. DPI を変えた時に合格線を px で持つか mm で持つか（ADR-0034 の確認事項 5 では出力の px）
13. 未校正の経路の出力の px と mm の対応（校正が無いので換算できない。合格線は出力の px のまま当てる）
14. 大域的な配置の確認が想定する取り違えの周期の上限は 768 px 未満。広い半径の外にある周期は見分けられない。実机の格子の周期は未測定
15. 帯に周期でない中身を持つ区画が 4 つ以上あることを、実際の図面の置き方が満たすか（実写で未確認）
16. 線形フェザーは重なりの全体で混ぜるので、その範囲をそのまま遷移帯として渡すとゲートの帯（重なりの内側）に収まらない。フェザーで合成する経路の遷移帯の定義（重みが 0 と 1 から離れた範囲など）は G3/G4 で決める

## 16. G1・G2 の実装（#386）

経路への接続（G3・G4）は別 Issue。ここでは純粋なライブラリ `a0_m2_seam_gate`（`src/m2/include/a0/m2/seam_gate.hpp`、`src/m2/seam_gate.cpp`、`src/m2/seam_gate_decision.cpp`）の作りと、草案から変えた所を書く。依存は `a0_m2_render` と STL だけで、カメラ・ファイル・時計を使わない。乱数を使わず、スレッド数によらず同じ結果を返す。原画像は読むだけ。

### 16.1 入力と API

| 関数 | 役割 |
|---|---|
| `PairSeamGeometry` | 未校正の相似（`render::PairRenderParameters`）から、`RenderPair` と同じ算術の写像を作る |
| `DocumentSeamGeometry` | 校正済みの写像。`RenderDocumentPair` と同じ `render::DocumentOutputToCamera` を使う（renderer から取り出して共有した） |
| `OverlapBand` | 二台の被覆の重なりを行ごとに求め、四方を指定の幅だけ内側に縮めた遷移帯 |
| `RequiredBandInsetPx` | 最初の探索半径の窓が両方の被覆に収まる内側への幅（校正済み 86 px、未校正 150 px） |
| `MeasureSeam` | 測定（G1）。原画像 2 枚、写像 2 つ、遷移帯（出力の行ごとの [begin, end)）、設計定数、合格線、予測（任意）、スレッド数 |
| `DecideSeamGate` | 判定（G2）。状態・理由・直し方・統計・最大の位置 |
| `UndeterminedSeamGate` | 経路が測れない時（方針や幾何が無い）の判定不能 |
| `SeamCutTransitionBand` | seam-cut の継ぎ目の道筋と混ぜ幅から、合成の遷移帯（行ごとの [begin, end)）を作る（16.11） |
| `CheckTransitionBandContained` | 遷移帯がゲートの帯に含まれるかを数える（16.11）。`MeasureSeam` は `SeamGateGeometry::transition` を渡されればこれを呼ぶ |
| `SeamGateReportJson` | 報告に埋め込む独立した JSON（`a0.seam-gate.v1`） |

測定器は合成後の画像を受け取らない。seam-cut と feather の判定が同じになることは試験で確かめる。配置は A 左・B 右だけ。

合格線と不確かさ（1 px と 0.2 px、#385）は `SeamGateLimits` として呼び出し側が渡す。コードに既定値は置かない（10 節の 5）。報告には値と出典（`source`）を書く。

### 16.2 測り方

1. 測定点: 遷移帯の左上を原点に 32 px おきの格子。区画は 128 px 角で、1 区画に 16 点
2. 各点で A と B を出力の格子に置いた輝度を、原画像から写像で Catmull-Rom 標本化する。帯を 256 行ずつの帯片に分け、帯片ごとに一度だけ作って点の間で使い回す（全体の P_A・P_B は持たない）
3. 照合の前に、出力の格子の輝度へ二項係数 [1 4 6 4 1]/16 の平滑を縦横に掛ける（A と B に同じ）。細い線を端数の位置へ標本化した時の位相による偏りを抑える。人工画像で、掛けない時の偏り約 0.03 px が約 0.015 px に下がった
4. 照合は輝度の勾配の強さの平均を引いた正規化相関（`zero_mean_correlation.hpp`、勾配と縮小は `overlap_estimation_detail.hpp`）。1/4 の縮小で探索窓の全体、1/2 と等倍で ±3 の近傍
5. 端数は #323 と同じ 3×3 の格子の半減を 7 段（最後の間隔 1/128 px）。各段で厳密に一意な最大を求め、曲線の当てはめは使わない。候補は平滑した輝度を Catmull-Rom で端数だけずらして作る（平滑とずらしは入れ替えられるので、平滑は点ごとに一度）。草案の「原画像から候補ごとに標本化」は 7360 幅で 180 秒に収まらなかったので変えた
6. 逆向き: B の端数の位置の patch を A の中で同じ手順で探し、元の点との差を往復の差とする

### 16.3 点の有効性（値の大小と無関係）

| 検査 | 内容 | 状態コード |
|---|---|---|
| 被覆 | patch が両方の被覆の内側 | `outside-coverage`（数えない） |
| 中身 | 勾配の強さ 8 DN 以上の画素が 32 以上（A か B） | `no-content` |
| 窓 | 探索窓・周期の窓が被覆の内側 | `search-window-unavailable` |
| 一意性 | 各段で最大が一つ、最大の近く以外に最大の 0.8 倍以上の極大が無い、近傍の端に無い | `ambiguous`・`flat-correlation` |
| 周期 | A の自己相関（1/4 の縮小、±2R）で原点の近く以外に 0.8 倍以上の極大が無い | `periodic` |
| 端 | 探索窓の端に当たれば半径を倍にして測り直す（最大 256 px）。それでも端なら無効 | `search-boundary` |
| 往復 | 往復の差 0.05 px 以下 | `round-trip-inconsistent` |
| 不確かさ | u = √(max(u_A→B, u_B→A)² + 往復²) + 0.01 px が 0.05 px 以下。u_peak = √((1 − r)/(c·N))（r は相関、c は峰の曲率、N は patch の画素数） | `uncertain` |

一方向の線（構造テンソルの固有値の比 0.1 未満）は、整数の探索を点を通る法線の上だけで行い（線に沿ってずれ続けると法線の推定誤差が混ざる）、端数は 2 次元で詰め、見えるズレは法線方向の成分 |n·d| にする（O2）。線に沿って同じ値の候補は中心に近い方を採る。

### 16.4 測り直しと確定

- 見えるズレ ＋ 0.2 px が 1 px を超えた有効な点は、3 通りで測り直す: patch を継ぎ目に沿って +16 px（無効なら −16 px）ずらす、patch を 96 px にする、勾配でなく輝度で相関を取る
- 順番はずらす・輝度・大きくする（最も重いものを最後）。2 通りが一致した時点、または 2 通りが一致しなかった時点で結果が決まるので、残りは測らない
- 元の値と max(3u, 0.1 px) の内側で一致する通りが 2 以上なら「確定」、それ以外は「未確認」。未確認の点は最大に入れない。未確認の点を 1 つでも持つ区画は、ほかに確定した点や一致する点があっても「中身があるのに測れない」にする（**#385 Q1 の所有者決定**。#386 の最初の実装では、区画の別の点が一致していれば測れた区画に数えていた）
- 値が大きいという理由で点を捨てる処理は無い。測り直しを始める条件だけが値によるが、確定は一致だけで決まる

### 16.5 区画の分類と予測

| 区画 | 条件 |
|---|---|
| 測れた（`measured`） | 未確認の点が無く、数える点（有効で、線以下か確定）が 2 つ以上あって一致する組がある、または確定した点がある。ただし測れた隣の区画すべてと代表値が 0.5 px より食い違う区画は「測れない」に移す（点は最大に残す） |
| 中身なし（`empty`） | 中身のある点が無い |
| 中身があるのに測れない（`unmeasurable-content`） | 未確認の点を 1 つでも持つ（**#385 Q1 の所有者決定**。同じ区画のほかの点が一致していても）、または上のどちらでもない |

中身なしの区画は、予測（`DisplacementPrediction`、校正の予測ズレ地図）があれば |予測| ＋ 予測の外れ m を値にする。m は数える点での |測った値 − 予測| の最大。予測が無い区画は値を作れず、3.5 節どおり合格に数えない（`unpredicted-empty-block` で不合格。予測が無い場合は #385 Q3 の所有者決定で当面不合格）。今の経路には予測地図が無いので、白い所がある撮影はこの理由でも不合格になる。

### 16.6 判定

`DecideSeamGate` は次の理由を順に集め、1 つでもあれば `fail`、無ければ `pass`。

| 理由 | 条件 | 直し方のコード |
|---|---|---|
| `seam-misalignment` | 数える点の最大 ＋ 0.2 > 1 | `retake-then-recalibrate` |
| `predicted-misalignment` | 中身なしの区画の予測値 ＋ 0.2 > 1 | `retake-then-recalibrate` |
| `unmeasurable-content` | 中身があるのに測れない区画が 1 つ以上 | `shift-paper-and-retake` |
| `no-measurable-block` | 測れた区画が 0 | `place-lines-on-seam-and-retake` |
| `unpredicted-empty-block` | 予測の無い中身なしの区画が 1 つ以上 | `use-calibrated-prediction` |
| `global-placement-mismatch` | 錨の広い探索で、局所の測定と別の位置に一意な峰があった錨が 1 つ以上（16.11） | `retake-then-recalibrate` || `global-placement-unverified` | 確かめられた錨が 4 区画に満たない（矛盾した錨が無い時）（16.11） | `place-distinctive-content-and-retake` || `transition-outside-band` | 合成の遷移帯の画素がゲートの帯の外にある（16.11） | `check-gate-band` |

`undetermined` は合格線が不正、または測定の時と違う合格線で判定しようとした時（測り直しの対象が変わるため）、合成の遷移帯が渡されていない時（`transition-band-not-supplied`）と、`UndeterminedSeamGate` を使った時。等しい値は通す（最大 0.8 は合格）。最大の位置は出力の px と区画で返す。浮きの判別（`failed-lift`、G5）はまだ無く、9 節の状態は `pass`・`fail`・`undetermined` と理由コードで表す。

報告の JSON は状態、理由と直し方、合格線と出典、統計（最大・その位置・2 番目・p95・平均・予測の最大・数えた点・確定・未確認）、区画の数（未確認の点で測れなくなった区画を含む）、配置の確認（`placement`: 広い半径・必要な錨・候補・評価・確かめた・矛盾・遷移帯の外の画素）、設計定数、格子、予測の有無と m、点の状態ごとの数、区画の一覧、測り直した点の一覧（3 通りの値と一致）を持つ。全点の一覧は持たない。読み込みと判定のやり直しは G3/G4 で報告に組み込む時に足す。

### 16.8 試験

`m2_seam_gate_contracts`（`tests/seam_gate_tests.cpp`）。画像の生成器 `tests/seam_gate_scene.hpp` は、ぼかした線の解析的な紙から A と B を直接計算し、ゲートのヘッダを使わない。B には既知のズレの場を入れる。雑音は 1 DN（決定的な擬似乱数）。

- 場面の大きさ: 局所の測定の試験（以下の精度・境界・局所のズレ・周期・大きなズレなど）の場面は 1100〜1400 px 幅で、広い窓（768 px）が B に収まる位置が無い。これらの試験は本番の設計定数のうち広い探索の半径だけ 128 px、必要な錨を 2 区画に下げた設計（`Reduced`）で走らせる。本番の定数は大域的な配置の試験と `--timing` の 7360 幅の場面で使う。遷移帯は試験の場面では帯と同じ範囲を渡す。白い区画を予測で補う試験は、中身を B の被覆に広い窓が収まる右半分に移した
- 精度: 線画・文字・一方向の線、4 通りの一定のズレ（端数 0.05〜0.71 px）で、数えた全点（各約 285 点）のズレの誤差が最大 0.033 px（二方向の点の偏り最大 0.016 px、rms 0.013〜0.021 px）。完了条件の 0.05 px 以内。時間の計測に使う密な 7360 幅の場面では、約 1 万点のうち数点が 0.05 px を超えた（二方向で最大 0.060 px、一方向で最大 0.075 px）。線の交わりが patch の縁にかかる所と見ている（※未確認）
- 境界: 記録を組み立てて、最大 0.8 は合格、0.8 のすぐ上は不合格。人工画像で 0.72 px は合格、0.88 px は確定した点で不合格
- 誤照合（#385 Q1 の所有者決定）: B だけで小さな印を 5 px ずらした点は、自身の検査では有効だが測り直しで未確認になる。その点を持つ区画は測れない区画（`unmeasurable-content`）になり、判定は不合格。誤照合の無い同じ場面は合格。試験名は `UnconfirmedPointIsUnmeasurable`（以前は `FalseMatchDoesNotFlip`、期待値は合格だった）
- 本物の局所のズレ: 約 100 px 角だけ 2 px ずらすと、確定した点で不合格、最大の位置はその場所
- 周期模様（6 px の縦縞）は測れない区画になり不合格。中身なしの帯は測れた区画 0 で不合格。予測ありの白い区画は合格に数え、予測が合格線を超えれば不合格、予測が無ければ不合格
- seam-cut と feather の合成は違うが、ゲートの報告はバイト単位で同じ。スレッド 3 と 1 で同じ。入力は変わらない
- 大きなズレ: 未校正の半径で約 10.7 px を 0.05 px 以内で測って不合格。校正済みの半径で 22 px は探索を広げて測る。一方向の線だけの場面では線に直交する成分だけを測る
- `PairSeamGeometry` の写像で原画像を標本化した値が `RenderPair` の片側だけの画素と一致する
- 机の格子に乗った外れた配置（#365 の自動位置合わせが狭い重なりで格子の周期 1 つ分ずれる場合）: 帯に図面の中身と机の格子があり、配置を周期 1 つ分ずらすと、周期 24・64・276・460・736 px（ライブ 640 幅の 24・40・64 px を撮影の幅に直した値を含む）のどれも不合格。短い周期は図面の中身のズレ（24・64 px）を確定して `seam-misalignment`、長い周期は図面の中身が探索の範囲の外で `unmeasurable-content`。格子だけの区画は約 0.01 px で揃って見える
- 大域的な配置（#392、`GlobalPlacementLatticeOnly`・`GlobalPlacementWithContent`・`GlobalPlacementContradicted`・`GlobalDecisionRules`・`GlobalDesignValidation`）: 2700×2000 の対（広い窓が B に収まる大きさ。帯は錨の取れる範囲 450×360 px に切る）。白い紙と格子だけで、配置を周期 1 つ分（96・128・276・460・736 px）ずらすと、校正済み（予測 0 を渡す）でも未校正（予測なし）でも合格しない。校正済みの 5 周期では局所の検査だけなら通り（測れた区画あり、理由は `global-placement-unverified` だけ）、広い探索が全錨を「繰り返し」にする。白紙も予測ありで合格しない。格子に周期でない図面を重ねた場面では、正しい配置が合格し（錨 12 区画のすべてが確かめられる）、周期 1 つ分ずらすと不合格。弱い相似形が局所の探索の位置にあり、強い一致が 300 px 先にある場面では、その錨が矛盾して `global-placement-mismatch`。遷移帯（`TransitionBandContainment`）は、帯の中なら合格、24 px 外へ出れば行数・画素数・最初の位置つきで不合格、渡さなければ判定不能

### 16.11 大域的な配置の確認と遷移帯の包含（#392）、#385 Q1 の所有者決定

#### 16.11.1 なぜ局所の検査では足りないか

局所の測定は、各点で A の patch を B の ±R（校正済み 16 px、未校正 48 px）で探す。周期の検査は A の自己相関を ±2R まで見る。帯の中身が格子や周期模様だけで、自動の位置合わせ（#365）が格子の周期 1 つ分ずれた位置に合っていると、格子は重なって見えるので、すべての点が往復照合も一意性も通り、見えるズレは 0 に近くなる。

- 校正の予測を渡した場合: 白い区画は予測で補われ、格子の区画は 0 で揃うので、周期が 2R を超える（試験では 276・460 px）と合格になる
- 未校正の場合: 周期の検査は ±96 px までなので、周期が 96 px を超える格子は「周期」にならない。帯の全体が周期 128 px の格子だけなら、予測なしでも合格になりうる

どちらも、帯の中だけを局所で見ても配置の誤りは見えない。見えるのは、周期でない中身が広い範囲で一意に対応する時だけである。

#### 16.11.2 確認の方法

1. **錨**: `measured` の区画ごとに、数える点のうち二方向の点で不確かさが最小のものを 1 つ選ぶ。一方向の線は線に沿った向きに平らなので、広い探索の錨にしない
2. **広い探索**: 錨の A の patch（64 px）を、B の ±`global_search_radius_px`（768 px）で、局所の測定と同じ段階的な探索（1/4 の縮小で窓の全体、1/2 と等倍で ±3 の近傍）で探す。各段で一意な最大が必要で、最大の近く以外に最大の 0.8 倍以上の極大があれば「繰り返し」
3. **結果**（錨ごと）
   - `verified`: 一意な峰が、局所の測定の変位から 2 px 以内にある
   - `contradicted`: 一意な峰が別の位置にある。局所では見えなかった強い一致が遠くにあるので、配置の誤りの証拠になる
   - `repeating`: 繰り返しがあり、一意でない。周期模様、格子、同じ形が並ぶ文字など
   - `search-boundary`・`flat-correlation`・`window-unavailable`: 窓の端に最大がある、平ら、広い窓が B の被覆に収まらない
4. **判定**: `contradicted` が 1 つでもあれば `global-placement-mismatch`。無くて `verified` が `global_minimum_anchors`（4 区画）に満たなければ `global-placement-unverified`。確かめる手段が無い（周期だけ、白紙、窓が収まらない）時は合格を出さない。予測の有無は関係しない
5. **評価する錨**: 候補の並びを、どの先頭部分も帯の全体に散らばる順（ビット反転）に並べ、先頭から `global_maximum_evaluations`（64）個までを評価する。スレッド数によらず同じ錨を同じ順で評価するので、結果はスレッド数によらない。ワーカーは最大 4（広い窓の作業用メモリが 1 ワーカー数十 MB のため）

#### 16.11.3 設計定数の理由

| 定数 | 値 | 理由 |
|---|---|---|
| 広い探索の半径 | 768 px | 取り違えは机の格子の周期 1 つ分。#365 のライブ画面の格子 24・40・64 px（640 幅）を撮影の幅（7360 px）に直すと 276・460・736 px。最大の 736 px の副峰を窓の内に入れ、周期の取り違えを繰り返しとして見つけるために 736 px より広くする。窓の一辺は patch と平滑の分を足して約 1600 px（B の被覆に収まる必要がある）。1024 px 以下は 1 ワーカーの作業用メモリの上限 |
| 必要な錨の数 | 4 区画 | 1 つの汚れや印の一致を配置の証拠にしない。配置は帯の全体で同じ写像なので、周期の取り違えは帯のどこでも同じ向きに出る。区画は別々で、各区画の錨は区画の中で独立に選ぶ |
| 評価する錨の上限 | 64 | 1 錨の広い窓の標本化と相関は Release で 1 ワーカーあたり約 0.6 秒（16.9 節の差から）。上限があれば時間は帯の広さによらない |
| 許容 | 2 px | 局所は端数まで、広い探索は整数の位置。取り違えは 24 px 以上なので、この値は取り違えの境ではない |

合否の線ではなく、G6 の実機の検証で見直す設計定数である（13 節 D392）。

#### 16.11.4 保証すること、しないこと

- 保証する: 帯の中に周期でない中身を持つ区画が 4 つ以上あり、その中身が ±768 px の範囲で局所の測定の位置にだけ一致する。この範囲に局所の測定と別の強い一致が無い
- 保証しない: ±768 px の外にある周期（13 節の 15 番）、中身が帯の一部にしか無い時の帯の他の部分の配置（配置は大域の写像として、帯の全体で同じ周期の取り違えが起きる前提）、広い窓が B の被覆に収まらない位置（重なりの左端から約 800 px 以内は錨にならない。7360 幅の重なりは約 3600 px で、右側に錨が取れる）
- 誤判定の向き: 錨が足りない、繰り返しがある場合は不合格の側に倒れる。図面の置き方が悪いと、実際は正しい配置でも撮り直しになる（直し方は `place-distinctive-content-and-retake`）

#### 16.11.5 遷移帯の包含

`SeamGateGeometry::transition` に、合成が A と B を混ぜうる範囲（行ごとの [begin, end)）を渡す。`MeasureSeam` が `band` に含まれるかを数え（`TransitionContainment`: 行数・画素数・最初の位置）、判定は外れていれば `transition-outside-band` で不合格にする。

- 渡されていなければ判定不能（`transition-band-not-supplied`）。合成の範囲を言えない経路が合格になるのを防ぐ。製品の経路は G3/G4 で必ず渡す（※仮定。不合格でなく判定不能にしたのは、利用者が撮り直して直るものでなく、経路の欠陥だから）
- seam-cut: `SeamCutTransitionBand(seam_x, width_pixels, output_width)` が、継ぎ目の道筋と混ぜ幅（`RenderPairSeamCut` は |x − seam| < width/2 を混ぜる）から、整数の画素に切り上げた範囲を返す
- 線形フェザーは重なりの全体で混ぜる。ゲートの帯は重なりの外周 `RequiredBandInsetPx`（校正済み 86 px、未校正 150 px）を測れないので縮めており、重なりの全体を遷移帯として渡すと必ず外れる。フェザーで合成する経路の遷移帯の定義（重みが 0 と 1 から離れた範囲、または遷移帯をフェザーの内側に限る合成）は G3/G4 で決める（15 節の 16 番）

#### 16.11.6 #385 Q1 の所有者決定

線を超えた点（見えるズレ ＋ 0.2 px が 1 px を超えた点）が測り直しで未確認のまま残った区画は、同じ区画のほかの点がどうであっても「中身があるのに測れない」にして不合格にする。

- 理由コードは既存の `unmeasurable-content`（直し方 `shift-paper-and-retake`）に寄せた。新しい理由は足していない。測れない中身があり、紙をずらして撮り直すのが直し方になることが同じなため。未確認で測れなくなった区画の数は結果の `unconfirmed_blocks` と報告の `blocks.unmeasurableByUnconfirmedPoint` で分かる
- 以前（#386）は、未確認の点があっても区画に一致する別の点があれば測れた区画に数え、判定は誤照合の無い場面と同じ合格だった。試験 `FalseMatchDoesNotFlip` は `UnconfirmedPointIsUnmeasurable` に改め、期待値を「誤照合の点のある区画は測れない区画になり不合格、誤照合の無い同じ場面は合格」に変えた
- 影響: 本当のズレが 0.8 px 付近の撮影で、ノイズで測り直しの対象になった点が 3 通りで一致しなければ、その区画で不合格になる。撮り直しが増える側の決定である
- 区画の分類の 1 行（`seam_gate.cpp`）と試験 `UnconfirmedPointIsUnmeasurable` がこの決定を実装している


#### 16.11.7 #385 の Q2・Q3（所有者決定。実装は変えていない）

- Q2: 1 px は、実際に書き出す画像の画素で数える。ゲートの写像は書き出す合成と同じ出力の格子（`RenderPair`・`RenderDocumentPair` と同じ算術）なので、測定の px はこの画素と同じ。縮小や別の DPI で書き出した画像の画素では数えない
