# 二台ライブビューの利用条件調査（開発時）

所有者の最新の明示指示は「2台同時制御ライブビューが最優先」。切り替え方式（#291/#295）を優先するとした記録は助手の解釈誤りとして撤回する。まず1台のPCで二台のLive Viewを継続取得・表示する#292を進め、次に映像Merge、最後に画像Mergeとする。切り替え方式と匿名ログ検証だけで、この完成条件を代替しない。

所有者の「確認してください」に基づき、Nikon公式ダウンロード手続きでD810を選択し、同意前の使用許諾表示を確認した。契約への同意、新たなSDKダウンロード、通信仕様本文の転載、実機操作は行っていない。ここでは調査結果と未解決事項を記録し、実装許可済みとは扱わない。追跡先は[#326](https://github.com/AbroadUmedaShota/A0CameraStitcher/issues/326)。

## 確認できたこと

- [公式FAQ](https://sdk.nikonimaging.com/information/ja/) Q12はSDKによる複数カメラの同時制御を非対応としている。手元のD810 Module ReadMe Revision 14も同様。これはSDKの対応範囲の説明であり、二つのprocessなら動く証明や、契約上の台数禁止の判断ではない。既存worker PoCは失敗している（#292）。
- [公式ダウンロード手順](https://sdk.nikonimaging.com/apply/guide)のRemote Control / D810選択後、step 3（`/apply/rule`）で表示された契約の識別子は`Remote-SDK-JP-Web-01`、改訂日は2025-05-15。開発時時点の表示を確認した。手元のSDK取得時に同意した版との一致は未確認。
- 第1条はdriver等の「ソフトウェア」と通信仕様等の「コマンド」を区別し、両方をSDKの構成品としている。第2条の明示的な使用・複製等の許諾は「ソフトウェア」を対象としており、通信仕様から独自のWPD/PTP実装を作る権利まで確認できない。
- 第1条・第7条ではSDKと関連技術情報が秘密保持の対象となる。第7条には例外とその条件もあるため、公開情報の存在だけを理由に仕様由来の命令値や手順を公開可能と判断しない。
- 追加確認: [公式配布案内](https://sdk.nikonimaging.com/apply/)はライブラリーと通信API仕様書をカメラ制御アプリへ組み込む用途で提供すると説明している。したがって、通信仕様の独自実装への利用が禁止されている、とも判断しない。個別の契約条項との適用関係と公開範囲が確認対象である。

結論: 契約本文は見つかったが、**(a) 同梱通信仕様を独自WPD/PTP実装に利用する範囲、(b) 仕様由来のソース・手順の公開範囲は、どちらも確認未完了**。非公開の実装なら許可される、とも断定しない。現在の公開契約だけで、過去に成立した契約内容を確定しない。

Nikonへの問い合わせそのものを必須条件と確定したわけではない。必要なのは利用・公開条件の根拠であり、公開情報・適用契約から確認できれば照会を必須にしない。以下の照会文案は不明点が残る場合の選択肢として準備したもの。所有者の依頼なしに送信しない。

## 次の開発と受入条件

所有者の最新の順序は「複数台同時制御 → 映像Merge → 画像Merge」。まず#292の二台とも動くライブビューを対象とする。既存の片側Live＋片側静止画を達成として数えない。

1. 利用・公開条件の根拠を確定し、#292へ結果を結び付ける。現状は調査済み・利用可否未解決。
2. ADR-0036（#307）の未承認事項を確定する。特にWPD session上限の改定を`FR-CAP-005`・`CON-003`・agent契約へ明記し、二台のWPD sessionと一つのcapture transactionを区別する。現在の「WPD session最大一つ」のまま二台同時取得を実装しない。SDK/WPDの重複、撮影・カード命令、設定変更、retryの禁止を保つ。
3. その後、開始・継続frame取得・停止の最小経路とsoftware契約試験を作る。二台それぞれの受信時刻と更新数を観測し、片側停止、USB切断、開始途中の失敗、binding無効化、撮影前の全closeを検証する。失敗した側をLive成功表示にしない。
4. 実機試作は対象・回数・時間・中止条件を具体化して別途確認する。机上の設計や一般的な開発指示だけで送信操作を始めない。fps・帯域・CPU・継続時間の受入値は実測前に決め、実績のない数値を保証しない。
5. 二台取得が成立してから、#309の画角計測と#308/#306の表示専用Cへ進む。静止画像Mergeの実写品質・通常アプリ接続はその後に再開する。

通信部分の着手前でも使える観測記録の評価ツールを[#327](https://github.com/AbroadUmedaShota/A0CameraStitcher/issues/327)で追加する。[形式と限界](DUAL_LIVE_OBSERVATION.md)を参照。これは保存済みの記録だけを読む準備作業で、B案の通信実装・agent契約変更・実機PoCではない。

契約本文のHTMLはignoredな`build/reference/nikon-d810-license-rule.html`にのみ保存した。公開対象のこの文書には条項の要旨・参照先だけを置く。ADRの状態、AGENTS.md、実機許可はこの調査では変更していない。

## 公開PTP実装の追加確認

所有者から提示されたClaudeの検討は、SDKを通さない制御経路があるという技術的な方向性では妥当。追加で以下の一次資料を確認した。

- [libgphoto2対応表](https://gphoto.sourceforge.io/proj/libgphoto2/support.php)はD810のLiveviewを掲載している。[プロジェクトREADME](https://github.com/gphoto/libgphoto2)はPTP/MTP対応とUnix系を主対象とすること、Microsoft OSのサポートがないことを明記する。Windows 11の本アプリへそのまま導入できる前提にはしない。
- [digiCamControlのNikon実装](https://github.com/dukus/digiCamControl/blob/master/CameraControl.Devices/Nikon/NikonBase.cs)はPortableDeviceLibとBaseMTPCameraを使用する。NikonのSDKを経由しない実装の比較候補になるが、他社を含むdigiCamControl全体がSDK非依存とは一般化しない。
- [公式2.0.0リリース記録](https://digicamcontrol.com/blog/news_2.0.0)には複数カメラLive Viewの追加とD810修正が記載されている。過去の製品の機能記録であって、本アプリ・このPC・D810二台の実機合格の代替にはしない。
- SDKを経由しなければSDK固有の同時制御制限を設計上避けられる。標準PTPだけでNikonのLive Viewが完結するわけではなく、vendor拡張、カメラごとの排他、driver、共有USB帯域、PC側処理の確認が必要。二台のUSB接続があっても帯域やhost処理が独立とは限らない。
- SDK同梱資料に依存しない公開実装を採用する案は、その公開実装と依存物の利用条件を確認して別に評価できる。SDK資料の調査だけを理由に、すべてのPTP経路でNikonへの照会が必須とはしない。今回は公開コードの転載・依存追加・transport変更はしていない。

既存実装の確認では、A/B切り替えはstop/close確認後に次を開始する形で実装済み。一方、撮影hostへのactivate後は画面がLive Viewを拒否するため、撮影後の再利用は#295の残課題。これは#292の二台同時取得の実装ではない。#295を先行するという直前の判断は撤回し、#292を最優先に戻す。表示確認とリモートAF/フォーカス駆動の追加は区別する。

最初の開発到達点は、CAM-A/Bの二画面がともに継続更新され、別々の受信時刻と状態を表示できること。映像Mergeに先立ち、二台の開始・停止、片側失敗、USB切断、撮影前の全closeを確認する。Windows WPD/PTPを第一候補とし、SDK同梱仕様に依存しない公開実装を根拠とする案と、その利用条件を整理する。SDK同梱仕様に基づく経路の未確認事項を、公開実装に基づく全経路でNikon照会が必須という結論へ拡張しない。ADR-0036の状態と実機試作の許可は、この優先順位訂正だけで変更しない。

所有者の「はい」と最新の到達順の指定を受け、[#328のメッセージ構築・検査部品](WPD_LIVE_VIEW_CODEC.md)をdevelopment-onlyで追加した。Microsoft公開仕様とMITの固定commitを根拠とし、SDK同梱仕様は使わない。カメラ列挙・open・送信・製品経路への接続がない独立試験部品で、ADR-0036全体の承認や実機許可を推定しない。これは公開経路の最初のsoftware部品に限る。#326のSDK資料利用の確認自体を完了とは扱わない。
