# 開発用C表示と自動候補・手動調整 (#333)

> #396 で方針変更し、#401 で切り替えた（ADR-0036 決定1 Accepted、ADR-0037 Accepted、[固定の合成の設計](design/fixed-composite.md)）。固定の合成条件（#399）がある時、CはJPEGと同じ条件と縦一直線の継ぎ目の関数（#398）で描き、手動の調整と自動位置合わせはCの位置を変えない（下の「固定の合成条件で描くC」）。条件が無い時は、従来の未校正の仮のCが残る（この節以降の本文は、その従来のCの挙動）。継ぎ目の列を人がCの画面でドラッグして決め、固定の合成条件に保存する操作は #403（未実装）。条件が v2（レンズの歪みを含む）の時は、下の「レンズの歪みを含む固定の合成条件（v2）で描くC」（#405 W5）。

所有者の仮設配置はAが左、Bが右。最終設置は机の上を写す吊り下げ方式の予定であり、現在の壁向き仮設を承認済みrig profileとして保存しない。ネイティブ開発画面の上段にA/B、下段に「C 仮Merge（未校正）」を表示する。Cはメモリ内のみで、撮影原本や保存JPEGの代用にしない。

既存の純粋計算 `a0_m2_render::RenderPair` を一方向に再利用する。A/Bを最大640画素辺へ縮小し、Bを右へ平行移動して重なりを線形featherする。Bの上下移動で両画像が存在する高さだけを残す。既定の重なり30%は表示開始用の仮値であり、光学的基準ではない。重なりと上下位置を1pxずつ変更できる。回転・倍率・台形・レンズ歪み・色合わせは本初期版の調整範囲に含まない。

所有者の追加依頼により「自動位置合わせ」ボタンで現在の二枚から平行移動の候補を一回求める。正規化相関の粗探索→画素単位の局所探索を行い、明るさの一様なgain/offsetに対して比較できるようにする。探索は横重なり10–90%、上下は最大100pxかつ画像高の1/4以内。相関値は診断値であり、合格閾値ではない。無地・一意に決まらない場合は候補を適用しない。候補を適用しても「要目視確認」であり、手動修正できる。似た文字の繰り返し、奥行き、回転、異なる画角、共通部分の不足は誤った候補の原因になる。#364 からボタンは下の「自動位置合わせ v2」を使う。

推定をフレームごとに更新せず、rig profileを自動学習しない。手動操作でrevisionが変われば計算中の古い結果を適用しない。カメラsession切り替え時も古いCを消す。A/Bのどちらかの入力が2秒以上古ければCを表示しない。片側の過去画像で現在の二台合成を偽らない。取得workerとは別の最新画像だけを処理するworkerで合成し、カメラ制御・セッション・ファイル保存をC側に持たせない。これは撮影時刻の同期を保証しない。

人工平面の既知移動、明るさ差、端数の縮小対応、上下crop、画素feather、無地、不正入力、片側更新停止を `preview_merge_contracts` で検査する。Release/Debugのソフトウェア合格と実機描画、本人の継ぎ目目視確認、最終設置後の校正受入は別々に記録する。#306の承認profileと保存JPEGと同じ幾何・色の製品Cは別の統合工程として残る。

## 固定の合成条件で描くC (#401、親 #396)

設置ごとの固定の合成条件（#399、`wpd-fixed-composite-condition.json`。`wpd-merge-policy.json` と同じフォルダ。書式は [WPD_STILL_REVIEW.md](WPD_STILL_REVIEW.md) の該当節）がある時、CはJPEG（#400）と同じ条件を、同じ縦一直線の継ぎ目の関数 `RenderPairFixedSeam`（#398）で描く。開発用ビルド（既定OFFの `A0_BUILD_WPD_DUAL_PREVIEW`）だけの経路で、条件は承認済みのprofileではない（画面に「未校正・未承認・表示専用」と出す）。Cは表示専用で、保存しない。撮影、保存の合成、補正の推定、条件の入力にしない（ADR-0036 決定1 の 5）。

**どのCを描くか**。条件ファイルは、ライブビューを始めるたび（撮影後の再開を含む）に一度読み、そのセッションの間は変えない。

| 状態 | Cの描き方 | 画面 |
|---|---|---|
| 条件が無い（ファイルが無い） | 従来の未校正の仮のC。重なりとB上下の手動調整、自動位置合わせ v2 が使える（以下の本文） | 「固定の合成条件がありません（未校正の仮の C）」を状態の行の頭に出す |
| 条件があり、使える | 下の方法で描く | 見出しに「固定の合成条件（未校正・未承認・表示専用）」、取付の向き、継ぎ目の列とその出どころ。状態の行に「ライブビューと撮影画像の対応は ※未検証（#309）」「倍率は補正しません」「保存しません」 |
| 条件があるが使えない（壊れている、取り付けの向きがこの画面と違う、ライブビューの大きさへ縮められない、縮めた継ぎ目の列が重なりの外） | Cを描かない | 画像の場所に理由を表示（「…Cを描きません」）。見出しは「固定の合成条件（未校正・未承認・表示専用）」のまま |

条件が無い時に従来のCを残すのは、条件を作る設置の時に、Cで位置を合わせる操作が要るため。ただし条件が無いと両台撮影のJPEGは合成されない（#400）ので、未校正のCは確認用で、JPEGの合成と同じ見え方ではない。そのため画面に未校正と出す。条件があるのに使えない時にCを描かないのは、条件が効いているように見せながら、JPEGが同じ理由で合成しない画像と食い違う絵を出さないため（ADR-0036 決定1 の 8 の考え方）。この時も、両台撮影の操作は止めない。保存するペアはCの絵を使わず、合成の可否は #400 の経路が同じ理由で表示する。

**描き方**（`a0/phase0/experimental/fixed_composite_preview.hpp`、純粋な関数。カメラ・ファイル・時計に依存しない）。

1. 向きを当てた縮小A/B（長辺 640 画素以下。従来のCと同じ縮小）の大きさ w×h と、条件の撮影画像の大きさ W×H から、sx = w/W、sy = h/H を求める。ライブビューのframeが撮影画像の全体を、縦横それぞれの比で縮めて写すという対応（#334 の正規化と同じ）を仮定する。**この対応は ※未検証（#309）**。実機で測るまで仮定のままで、画面と文書に出す。違っていれば、Cで見える継ぎ目の列がJPEGの別の場所に来る
2. `ScaleFixedSeamCondition`（#398）で、写像を S·H·S⁻¹、cropと継ぎ目の列を縮尺の比で縮める
3. 混ぜ幅と明るさの窓を縮める（次の項）
4. `RenderPairFixedSeam` で描く。明るさの比は、毎frame、同じ関数の中で継ぎ目の窓のAとBの輝度から求めてBに掛ける。写像と継ぎ目の列は動かない。frameの内容で変わるのは明るさの比だけ。倍率は補正しない（撮影の前に倍率を知らない。ADR-0037）。JPEGとの幾何の違いは、縮尺と、上限以内の倍率の差だけ

**混ぜ幅と明るさの窓の縮尺**（[設計](design/fixed-composite.md) 3.4 節）。`kSeamBlendDesign`（混ぜ幅 8、窓の半幅 32、行方向のならし 128 行。承認値ではない）は撮影画像の画素で決めた値なので、Cでは列方向を sx、行方向を sy で縮め、整数画素に丸めて最小 1（使わない端の余裕は最小 0）にする（`ScaleSeamBlendSettings`）。撮影画像の同じ長さを混ぜ、測ることになり、CとJPEGの見え方が縮尺の比で対応する。縮尺が約 0.1 なら混ぜ幅は 1 画素（縮めた8画素は0.8画素で、その解像度では1画素の切り替えと同じ）、窓の半幅は 3 画素になる。C用の別の定数は持たない（CとJPEGが構造的に違う見え方になり、承認されていない値が増えるため）。

**原寸で描ける列がCで描けなくなる場合**。混ぜ幅の半分は、Cでは 0 画素になる。残る原因は、縮めた継ぎ目の列と縮めた帯の端が、それぞれ整数画素へ丸められること（`ScaleFixedSeamCondition` は、cropの端が縮めた画素の 2 未満動くと書いている）だけである。`PlanFixedPreview` は、縮めた列、その左右 1 画素、左右 2 画素の順に `CanRenderFixedSeam` を試し、最初に通る列を使う。寄せた量は画面の状態の行に「継ぎ目をCの画素に合わせて N px 左（右）へ寄せています」と出す。2 画素以内に通る列が無ければ、Cを描かず理由を出す。撮影画像の幅が W、Cの幅が w なら、Cの 1 画素は撮影画像の約 W/w 画素。寄せるのは帯の縁に近い列だけで、帯の中央（条件を作った時の初期値）は寄せない。原寸で合わない列は、JPEGの経路（#400）が `seam-outside-overlap` で合成しない。Cはその判定を再現せず、縮めた画素で2画素以内の丸めの範囲だけ、原寸で合わない列を描きうる（条件ファイルを手で編集した場合に限る）。

**位置合わせのボタン**。条件が使えるか使えないかにかかわらず、条件ファイルがある間は、「重なり ±1px」「Bを上へ/下へ」と「自動位置合わせ」はCの位置を変えない。自動位置合わせは推定も走らせない。ボタンを押すと、状態の行に「固定の合成条件で描いているため、位置合わせはCの位置を変えません（ライブビューと撮影画像の対応は ※未検証 #309）」と出す。固定の合成条件とのずれの表示と、再校正の案内は #402。

**継ぎ目の線**。「継ぎ目の線を表示」のチェックで、Cの上に継ぎ目の縦線を重ねる（入切できる。既定は入）。色は #400 の保存結果の縦線と同じ桃色（RGB 255,0,255）。表示だけで、Cの画素は変えない。線の位置は、描いたframeの継ぎ目の列（寄せた後）の中心。列を人がドラッグして動かす操作は #403。

**ログ**（画素は書かない）。条件の読み込み: `C fixed_composite_condition=present|absent|invalid`（present は条件ファイルの SHA-256、継ぎ目の列と出どころ、取付の向き）。描き方の決定: `C composite mode=fixed-composite|unavailable|uncalibrated view=WxH …`（fixed-composite は撮影画像の列、縮めた列、寄せた量、縮めた混ぜ幅・窓・ならし、`correspondence_verified=0 uncalibrated=1 quality_accepted=0`、unavailable は理由コード）。2 秒ごとの `C merged_frames=…` に、条件で描いている時は継ぎ目の列と明るさの比の範囲を足す。

**確認**。`preview_fixed_composite_contracts`（`tests/fixed_composite_preview_tests.cpp`、カメラ不要）: 縮めた条件の写像・継ぎ目の位置・Bの置き場所が縮尺の比で原寸の合成と一致すること（平らな画像にBだけの白い縦棒を置き、原寸と縮めたCで棒と継ぎ目の全体座標を比べる。縦横比が違うビューを含む）、混ぜ幅と窓の縮尺、継ぎ目の列を帯の端の近くへ動かしても原寸で描ける列がCでも描けること（寄せた量の上限以内）、帯の外の列を描かないこと、条件が無い・壊れている・向きが違う・大きさが合わない時の分岐、frameごとに明るさの比だけが変わること、画面の文言に「※未検証」と「未承認」が入ること。`preview_fixed_c_ui_contracts`（`--fixed-c-ui-smoke`）: 合成のframeと条件を使い、実際の合成worker・描画・ボタン・チェックで、条件で描く時に桃色の縦線が継ぎ目の列に1本出てチェックで消える・位置合わせのボタンが重なり・上下・revisionを変えない、条件が使えない時にCを描かず両台撮影は受け付ける、条件が無い時は従来どおり手動調整が効き線が出ない、を確認する。どちらも設定ファイルを読み書きしない。実機のライブビューで撮影画像と同じ範囲を写しているか（`S`）は、実機で別に確かめる（#309）。

## レンズの歪みを含む固定の合成条件（v2）で描くC (#405 W5、親 #405)

> 設計は [レンズの歪みを含む固定の合成条件](design/fixed-composite-lens.md) の 6 節（C）、3.7 節（取り付けの向き）。上の「固定の合成条件で描くC」は v1 の条件（相似の写像）の説明で、v1 の描き方、出力、文言は変えていない。

条件ファイルは v1 と同じ名前（`wpd-fixed-composite-condition.json`）で、`schema` が `a0.fixed-composite-condition.v2` ならこの経路になる。v2 の条件は写像の値を持たず、同じフォルダの校正済み draft の rig profile を SHA-256 と fingerprint で参照する（W1）。条件を読むのは両台撮影の JPEG の経路と同じ `SelectFixedComposite`（`a0/m2/experimental/fixed_composite_selection.hpp`）で、Cはそれを `LoadFixedPreviewSource` から呼ぶだけにしてある。版の振り分けも、条件が無い・壊れている・profile が無い（`profile-absent`）・profile が違う（`profile-differs`。差し替わった、書き換わった、使えない）の判定も JPEG と同じで、Cを描かない時の理由の符号も JPEG の「合成しない理由」（[WPD_STILL_REVIEW.md](WPD_STILL_REVIEW.md) の「v2 の JPEG の経路」）と同じ。画面の文言は、`profile-absent` と `profile-differs` では JPEG の文の後ろに「Cを描きません」を付けたもの。profile も条件も書き換えず、承認もしない。

| 状態 | Cの描き方 | 画面 |
|---|---|---|
| 条件が無い | 未校正の仮のC（上の表のとおり） | 変わらない |
| v1 の条件があり、使える | v1 のC（上の「描き方」） | 変わらない |
| v2 の条件があり、使える | 下の方法で描く | 見出しに「固定の合成条件 v2（レンズの歪みを補正、未承認・表示専用）」、取付の向き、継ぎ目の列（出力ラスタの画素）とその出どころ。状態の行に「ライブビューと撮影画像の対応（S）は ※未検証（#309）」「校正の写像（draft、未承認）」と profile の識別子、「倍率は補正しません」「保存しません」 |
| 条件があるが使えない（壊れている、profile の欠落・不一致、向きが違う、大きさが合わない、被覆できない、継ぎ目が重なりの外） | Cを描かない | 画像の場所に理由（「…Cを描きません」）。見出しは v2 が読めていれば「固定の合成条件 v2（未承認・表示専用）」 |

**写像**（`PlanFixedPreviewV2`、`LiveViewOutputToCamera`。`a0/phase0/experimental/fixed_composite_preview.hpp`）。Cの出力の画素 (i,j) について、次の順に位置を求める。JPEG と同じ関数 `render::TryProjectDocument`（レンズの係数）を使い、`S` と向きは座標の計算で、画素を作らない。

1. 出力画素 → 文書の点（mm）: `X = left + (i+0.5)·p_C`、`Y = top + (j+0.5)·p_C`
2. 文書 → 撮影画像（7360×4912）の生画素: 校正済み draft の写像とレンズ（A と B の別々）
3. 撮影画像 → ライブビューの画素: `S(u,v) = (sx·u, sy·v)`、`sx = w/7360`、`sy = h/4912`。**この対応は ※未検証（#309）**。v1 のCと同じ仮定で、半画素の差も補正しない
4. `rotated-180` の時だけ、向きを当てたライブ画像の座標へ: `(w-1-u, h-1-v)`

倍率は補正しない（k = 1。撮影の前に倍率を知らない、ADR-0037）。

**格子**。Cの出力は、JPEG と同じ文書の領域を、間隔 `p_C = p / s` で区切った格子にする。`p = 25.4/DPI` mm は条件の出力ラスタのもの、`s = sx`（ライブビューの撮影画像に対する縮尺）。列数と行数は領域の中に収まる数（切り捨て）で、すべての標本が JPEG で覆えることを確かめた領域の中に入る。格子は文書の上で縦横同じ間隔で、ライブビューの縦横比が撮影画像と違っても、違いは `S` の縦横の倍率の中で扱う。

**継ぎ目と混ぜ幅**。JPEG の列 c の中心と同じ文書の位置を通るCの列は `(c+0.5)·s-0.5` で、これを丸め、v1 のCと同じく左右 2 画素まで近い順に `CanRenderMappedFixedSeam` で確かめて、最初に通る列を使う。寄せた量は状態の行に「継ぎ目をCの画素に合わせて N px 左（右）へ寄せています」と出す。混ぜ幅と明るさの窓は `ScaleSeamBlendSettings` で縮める（縦横とも `s`）。C用の別の定数は持たない。寄せた列は保存せず、条件にも入れない。

**合成**。`RenderMappedFixedSeam`（W2）。JPEG と同じ混ぜ方、同じ明るさの比の測り方で、比は毎 frame、2 枚の frame から求めて B に掛ける。写像と継ぎ目の列は動かない。frame の内容で変わるのは明るさの比だけ。

**座標の表**。写像はセッションの間変わらないので、出力画素ごとの A と B の位置（向きを当てたライブ画像の座標）を、計画を作る時に一度だけ表にし、frame ごとには表を引いて標本化する。表は座標で画像ではなく、ライブ画像の標本化は 1 回のまま。表の値は直接の写像の値とビットまで同じ（試験で全画素を比べる）。Releaseで、実際の設置の規模（シート全体の領域）の格子を、表を引く場合と画素ごとに写像を評価する場合で比べ、表を引く方が速く、表の大きさは格子の画素数 × 2 台 × 16 バイトで抑えられるため、表を作る方に決めた。表を作る時間は、ライブビューを始めて最初の frame を決める時の 1 回だけ。計測の数値は Issue の報告に書き、ここには書かない（機種と設置で変わるため）。標本数の上限（`kFixedPreviewMaximumOutputPixels`）は表の大きさを抑える資源の上限で、光学の値ではない。

**取り付けの向き**。`rotated-180` の時、ライブ画像は従来どおり縮小の後でメモリの中で 180° 回してから渡される（`OrientRenderInput`）。v2 の写像は、保存された順の画素に対して定義されているので、Cの写像の側で `(w-1-u, h-1-v)` を足して合わせる。画素を入れ替えるだけなので、標本化は増えない。条件が持つ向きと画面の向きが違えば、v1 と同じく `orientation-differs` でCを描かない。

**位置合わせのボタン、継ぎ目の線、撮影**。v1 と同じ。条件ファイルがある間は、位置合わせのボタンはCの位置を変えず、推定も走らせない。継ぎ目の線は寄せた後の列の中心に引く。Cの画素は保存せず、撮影、保存の合成、補正の推定、条件・profile の入力にしない。両台撮影はCの絵に依らず受け付ける。

**ログ**（画素は書かない）。条件の読み込みの行に `version=1|2` を足し、条件ファイルがあって使えない時は `reason=` に理由の符号（`condition-invalid`・`profile-absent`・`profile-differs`）を出し、v2 は条件と profile の SHA-256、profile の fingerprint、出力ラスタの大きさと DPI、継ぎ目の列を出す。描き方の決定の行（`C composite mode=…`）に `version=2 grid=WxH grid_pitch_mm=… coordinate_table=1` を足す。

**確認**。`preview_fixed_composite_v2_contracts`（`tests/fixed_composite_preview_v2_tests.cpp`、カメラ不要、引数は rig profile v2 の共通試験ベクトルのフォルダ）:

## 取り付けの向き（normal / rotated-180） (#361)

吊り下げリグでは二台とも画像の左右が部屋と逆に写り、実際の重なりがAの左端とBの右端に来る。所有者の決定によりカメラはそのままにし、アプリ側で取り付けの向きを `normal`（既定、従来どおり）と `rotated-180` から選ぶ。`rotated-180` ではCに使う縮小A/Bを両方とも180°回転（行と列を同時に反転）してから、Aを左、Bを右に並べる。自動位置合わせ、重なりとB上下の手動調整、合成はすべて回した後の座標で行う。上段のA/B表示は受け取ったままで回さない。90°・鏡像・片側だけの回転、Bの数度の回転、明るさ・色の差は対象外。

向きは起動引数、ローカル設定ファイル、`normal` の順に決める。

- 起動引数: `A0CameraStitcher.WpdDualPreview.exe --seconds 0 --mount-orientation rotated-180`。`--seconds N [試験mode]` の後ろに付く一組だけを受け付け、従来の引数の形は変えない。`scripts/Start-WpdDualLivePreview.ps1 -MountOrientation rotated-180` も同じ値を渡す。省略時は引数を渡さない。
- 設定ファイル: カメラ登録 `camera-map-wpd.json` と同じフォルダ（`%LOCALAPPDATA%\A0CameraStitcher\phase0`）の `wpd-mount-orientation.json`。

```json
{"schema":"a0.wpd-mount-orientation.v1","mountOrientation":"rotated-180"}
```

ファイルが無ければ `normal`。二つの欄以外の欄、重複欄、未知のschemaや値、大文字違い、4096byte超、通常ファイル以外は起動を拒否し、hardware leaseの取得やカメラのopenに進まない。先頭のUTF-8 BOMだけは許す。値は起動時に一度だけ読み、表示中は変わらない。ログに `mount_orientation=<値> source=argument|settings|default originals_rotated=0` を残す。Cを作らない後片付け（`--stop-live-only`、`--capture-a/-b`）では読まない。

Cの見出しに「取付の向き: 通常」または「取付の向き: 180°回転（A/Bを回して合成）」を表示する。「両台撮影 → 仮Merge保存」はCの重なり・上下位置と一緒にこの向きを保存JPEG側へ渡し、原画像を復号した後のメモリ上の入力だけを同じ向きで回して合成する（[WPD_STILL_REVIEW.md](WPD_STILL_REVIEW.md) の #361 の節）。PCに保存する `original.jpg` は撮ったままで、回転も書き換えもしない。

`normal` の画素、自動位置合わせ、既存試験の期待値は変わらない。相関値に合格線を設けず、自動候補の採否条件も変えない（採否の条件は後の #364 で v2 に変えた）。`preview_merge_contracts` は奇数・偶数の幅と高さでの180°回転の画素対応、`rotated-180` の合成で回したAの外側（元のAの右端）が左端に来ること、Aの左端とBの右端が重なる人工画像を回した後の座標で既知の移動量を見つけること、見出しの文字、設定ファイルの厳格な読込を検査する。吊り下げリグでの実機確認（#360 で記録した回転前の自動位置合わせ結果との比較）は別に記録する。

## 自動位置合わせ v2 (#364)

> #396 で方針変更（ADR-0037 Accepted、[固定の合成の設計](design/fixed-composite.md)）。v2 はCの位置を変えず、固定の合成条件とのずれを表示し、大きければ再校正を案内する。#401 で、固定の合成条件のファイルがある間は、ボタンを押してもCの位置を変えず推定も走らせない（上の「固定の合成条件で描くC」）。ずれの表示と再校正の案内は #402 で切り替える。条件が無い時の未校正のCでは、以下の挙動のまま。

「自動位置合わせ」ボタンは #364 から推定器 v2 を使う。上の段落の推定器（`EstimatePreviewTranslation`）は試験の比較対象として残し、ボタンからは呼ばない。設計の背景と原因の見立ては [M2_AUTO_OVERLAP.md](M2_AUTO_OVERLAP.md) の 3 節と 5.4 節。

v2 は `a0_m2_overlap_estimation`（`a0/m2/experimental/overlap_estimation.hpp`）の純粋な関数で、カメラ・ファイル・時計を持たず、乱数を使わない。phase0 のライブCと、後の撮影JPEGの推定（#362 I3）の両方から呼ぶ。扱うのは平行移動だけで、探索範囲は手動調整と同じ（横重なり10–90%、上下は最大100pxかつ画像高の1/4以内）。入力は #361 の向きを当てた後の縮小A/B。

- 比べる量: 輝度の前進差分から作った勾配の強さ。周辺減光・影・全体の明るさの差のような、ゆっくり変わる明るさを先に落とす
- 多段: 勾配の強さを2×2の平均で縮め、大きい辺が96px以下になるまで段を作る（640px幅で4段）。最も粗い段で全範囲を探し、局所最大を上位8つまで残して、細かい段ごとに2倍の位置の±2pxで探し直す。同じ位置に集まった候補は一つにまとめる
- 並べ方: 重なった長方形の勾配の正規化相関 r と標本数 n から、`atanh(r)·√(n−3)` を根拠の強さとして並べる。小さい重なりで偶然高い相関が出た候補が、広い重なりの候補を追い越さないようにするため。r も根拠の強さも診断値で、合格線ではない
- 相関の計算: M2 の照合（#318）と同じ関数（平均を引いて正規化した内積）を共有する。写した二つ目の実装は持たない

数値のしきい値を使わない次の検査に一つでも通らなければ `undetermined`（判定不能）を返し、Cの位置を変えない。通れば `estimated-not-judged`（基準による判定なし）として位置を適用する。承認されたしきい値が無い間はこの扱いにする（#364 の仮定。M2_AUTO_OVERLAP.md 14.2 節 Q9 の推奨）。

| 理由コード | 条件 |
|---|---|
| `no-candidate` | 比べられる模様が無く、相関を計算できる位置が一つも無い |
| `tied-candidates` | 最大の候補と同じ強さの候補がある（局所の探索の中を含む） |
| `search-boundary` | 最大の候補が探索範囲の端にある。範囲の外にある本当の位置を端に寄せて出さない |
| `refinement-boundary` | 細かい段で、探し直した窓の端（範囲の端ではない側）に最大が来た。粗い段の山が本物の山を含んでいない |
| `reverse-mismatch` | A/Bを入れ替え、両方を180°回して同じ探索をやり直すと、同じ位置に戻らない。粗い段では段の区切りと差分の向きが変わるので、粗い段の標本の取り方でしかたどり着けない山はここで落ちる。いちばん細かい段（元の画素）は、行きの勾配を180°回した同じ標本で比べる。整数の位置への丸めが往復で一度だけになり、真のずれが半画素に近い時に行きと帰りで1px違うことが無くなる。往復でたどり着いた同じ位置の点数は同じ標本から計算する（足す順が逆なので、丸めの差で並ぶ同点だけは例外）ので、最終の順位は往復で一致する。往復照合が見るのは、粗い段の道筋の違いだけ。段が1つだけの時（80×60 の試験を含む）は元の画素で全部の位置を比べているので、往復は同じ比較の繰り返しになる |

ログには推定ごとに一行 `C auto_overlap_v2 status=... reason=... orientation=... levels=... candidates=... best_overlap_px=... best_vertical_px=... best_correlation=... best_evidence=... best_samples=... second_overlap_px=... second_vertical_px=... second_evidence=... evidence_gap=... reverse_overlap_px=... reverse_vertical_px=... applied=0|1 quality_accepted=0` を出す（候補が無い欄は省く）。`second_*` と `evidence_gap` は、最上位から縦横どちらかに2px以上離れた最初の候補と比べる。細かい段で二つの粗い山が隣り合う画素に寄ると、その隣は最上位の山の肩で、別の位置の候補ではないため。適用した時は、従来の `C auto_translation_proposal=1 overlap_px=... vertical_px=... correlation=... quality_accepted=0` も同じ形で続けて出す。画面は、適用時「自動位置を適用（基準による判定なし・要目視確認）」、判定不能時「自動位置を決められません（理由）。Cの位置は変えていません」。推定の間にA/Bのどちらかが2秒以上古くなった時と停止中は、結果を捨てて `C auto_overlap_v2 discarded=stale|stopping` を一行出し、画面は、古くなった時は「映像が古くなったため適用していません。もう一度押してください」、停止中は「停止したため適用していません」にする。推定の間に手動調整した時は、手動調整の表示とログが先に出ているので、捨てた結果のログは出さない。

設計案（5.4 節）のうち、次は I1 に入れていない。事前の位置の近くを先に探すこと（保持値は I2・I8）、比べる標本の数の下限（数値なので所有者決定欄 N1 の扱いと合わせる。代わりに上の根拠の強さで並べる）、続く frame で同じ結果を求めること（回数 N5 が未設定）、タイルの検証と相似（I2）。

`preview_merge_contracts` は次を検査する。既知の平行移動（80×60 と 320×200、Bは明るさを2倍＋20）を v2 が見つけ、往復照合も同じ位置に戻ること。`rotated-180` の吊り下げの人工画像で、回した後の座標で既知の移動量を見つけること。無地は `no-candidate`、範囲の外（重なり95%）の本当の位置は `search-boundary` で適用しないこと。入力の画素を変えないこと。640×427 の負の対照4つ（周辺減光、机の格子のような周期模様、ぼけた床に見立てた別の深さの帯、小さい重なりの位置に置いた似た模様。正解は重なり310px・B上下12px）で、上の段落の推定器が外れること（試験の中で外れた位置を出力する）と、v2 が4つとも正しい位置を適用し、往復も同じ位置に戻ること（判定不能への劣化も検出するため、対照ごとに今の結果で固定する）。B を縦に半画素ずらした人工画像2つで、正しい位置（真は B上下12.5px なので12も13も正しい。今の結果の12pxで固定）を適用し、往復も同じ位置に戻ること。真の重なりが96px（15%）で広い格子の線が囮になる5つは、良し悪しを判定せず、今の結果を入力ごとに固定する。正しい位置を適用するのは2つ。判定不能の2つ（周期40px）は、周期24pxと40pxの格子が揃う位置の一つがちょうど探索範囲の端（dx=64、重なり576px）に来て、行きか帰りの最上位がそこで止まった偶然による（`search-boundary` と `reverse-mismatch`）。残る1つ（周期64px・線の濃さ80・描線30）は、格子の揃う重なり544pxを行きと帰りの両方で選んで適用し、外れた位置のまま記録している。相関が近いと標本の多い広い重なりを上に並べるためで、外れは珍しくない。レビューで真の重なり84〜120px（13〜19%）、周期24/40/64px、線の濃さ40/80、描線20/30/40/60の96通りを比べると、43通りで外れた位置を適用した（判定不能24、正解29。描線60でも24通り中3通りが外れ）。直すには数値を使わない検査を新しく足す必要がある（#304）。なめらかな模様と1画素の模様を別のずれで重ねた2つで、粗い段と細かい段が違う位置を指し、`reverse-mismatch` と `refinement-boundary` になること。最上位の隣の画素を次点として扱わないこと。同じ入力で二回呼んで同じ結果になること。normal と rotated-180 の合成の既存の契約は変えない。人工画像の結果であり、吊り下げリグでの安定性（同じ位置か判定不能になるか）は実機で別に記録する。
