# 開発用C表示と自動候補・手動調整 (#333)

所有者の仮設配置はAが左、Bが右。最終設置は机の上を写す吊り下げ方式の予定であり、現在の壁向き仮設を承認済みrig profileとして保存しない。ネイティブ開発画面の上段にA/B、下段に「C 仮Merge（未校正）」を表示する。Cはメモリ内のみで、撮影原本や保存JPEGの代用にしない。

既存の純粋計算 `a0_m2_render::RenderPair` を一方向に再利用する。A/Bを最大640画素辺へ縮小し、Bを右へ平行移動して重なりを線形featherする。Bの上下移動で両画像が存在する高さだけを残す。既定の重なり30%は表示開始用の仮値であり、光学的基準ではない。重なりと上下位置を1pxずつ変更できる。回転・倍率・台形・レンズ歪み・色合わせは本初期版の調整範囲に含まない。

所有者の追加依頼により「自動位置合わせ」ボタンで現在の二枚から平行移動の候補を一回求める。正規化相関の粗探索→画素単位の局所探索を行い、明るさの一様なgain/offsetに対して比較できるようにする。探索は横重なり10–90%、上下は最大100pxかつ画像高の1/4以内。相関値は診断値であり、合格閾値ではない。無地・一意に決まらない場合は候補を適用しない。候補を適用しても「要目視確認」であり、手動修正できる。似た文字の繰り返し、奥行き、回転、異なる画角、共通部分の不足は誤った候補の原因になる。#364 からボタンは下の「自動位置合わせ v2」を使う。

推定をフレームごとに更新せず、rig profileを自動学習しない。手動操作でrevisionが変われば計算中の古い結果を適用しない。カメラsession切り替え時も古いCを消す。A/Bのどちらかの入力が2秒以上古ければCを表示しない。片側の過去画像で現在の二台合成を偽らない。取得workerとは別の最新画像だけを処理するworkerで合成し、カメラ制御・セッション・ファイル保存をC側に持たせない。これは撮影時刻の同期を保証しない。

人工平面の既知移動、明るさ差、端数の縮小対応、上下crop、画素feather、無地、不正入力、片側更新停止を `preview_merge_contracts` で検査する。Release/Debugのソフトウェア合格と実機描画、本人の継ぎ目目視確認、最終設置後の校正受入は別々に記録する。#306の承認profileと保存JPEGと同じ幾何・色の製品Cは別の統合工程として残る。

## 取り付けの向き（normal / rotated-180） (#361)

吊り下げリグでは二台とも画像の左右が部屋と逆に写り、実際の重なりがAの左端とBの右端に来る。所有者の決定によりカメラはそのままにし、アプリ側で取り付けの向きを `normal`（既定、従来どおり）と `rotated-180` から選ぶ。`rotated-180` ではCに使う縮小A/Bを両方とも180°回転（行と列を同時に反転）してから、Aを左、Bを右に並べる。自動位置合わせ、重なりとB上下の手動調整、合成はすべて回した後の座標で行う。上段のA/B表示は受け取ったままで回さない。90°・鏡像・片側だけの回転、Bの数度の回転、明るさ・色の差は対象外。

向きは起動引数、ローカル設定ファイル、`normal` の順に決める。

- 起動引数: `A0CameraStitcher.WpdDualPreview.exe --seconds 0 --mount-orientation rotated-180`。`--seconds N [試験mode]` の後ろに付く一組だけを受け付け、従来の引数の形は変えない。`scripts/Start-WpdDualLivePreview.ps1 -MountOrientation rotated-180` も同じ値を渡す。省略時は引数を渡さない。
- 設定ファイル: カメラ登録 `camera-map-wpd.json` と同じフォルダ（`%LOCALAPPDATA%\A0CameraStitcher\phase0`）の `wpd-mount-orientation.json`。

```json
{"schema":"a0.wpd-mount-orientation.v1","mountOrientation":"rotated-180"}
```

ファイルが無ければ `normal`。二つの欄以外の欄、重複欄、未知のschemaや値、大文字違い、4096byte超、通常ファイル以外は起動を拒否し、hardware leaseの取得やカメラのopenに進まない。先頭のUTF-8 BOMだけは許す。値は起動時に一度だけ読み、表示中は変わらない。ログに `mount_orientation=<値> source=argument|settings|default originals_rotated=0` を残す。Cを作らない後片付け（`--stop-live-only`、`--capture-a/-b`）では読まない。

Cの見出しに「取付の向き: 通常」または「取付の向き: 180°回転（A/Bを回して合成）」を表示する。「両台撮影 → 仮Merge保存」はCの重なり・上下位置と一緒にこの向きを保存JPEG側へ渡し、原画像を復号した後のメモリ上の入力だけを同じ向きで回して合成する（[WPD_STILL_REVIEW.md](WPD_STILL_REVIEW.md) の #361 の節）。PCに保存する `original.jpg` は撮ったままで、回転も書き換えもしない。

`normal` の画素、自動位置合わせ、既存試験の期待値は変わらない。相関値に合格線を設けず、自動候補の採否条件も変えない（採否の条件は後の #364 で v2 に変えた）。`preview_merge_contracts` は奇数・偶数の幅と高さでの180°回転の画素対応、`rotated-180` の合成で回したAの外側（元のAの右端）が左端に来ること、Aの左端とBの右端が重なる人工画像を回した後の座標で既知の移動量を見つけること、見出しの文字、設定ファイルの厳格な読込を検査する。吊り下げリグでの実機確認（#360 で記録した回転前の自動位置合わせ結果との比較）は別に記録する。

## 自動位置合わせ v2 (#364)

「自動位置合わせ」ボタンは #364 から推定器 v2 を使う。上の段落の推定器（`EstimatePreviewTranslation`）は試験の比較対象として残し、ボタンからは呼ばない。設計の背景と原因の見立ては [M2_AUTO_OVERLAP.md](M2_AUTO_OVERLAP.md) の 3 節と 5.4 節。

v2 は `a0_m2_overlap_estimation`（`a0/m2/experimental/overlap_estimation.hpp`）の純粋な関数で、カメラ・ファイル・時計を持たず、乱数を使わない。phase0 のライブCと、後の撮影JPEGの推定（#362 I3）の両方から呼ぶ。扱うのは平行移動だけで、探索範囲は手動調整と同じ（横重なり10–90%、上下は最大100pxかつ画像高の1/4以内）。入力は #361 の向きを当てた後の縮小A/B。

- 比べる量: 輝度の前進差分から作った勾配の強さ。周辺減光・影・全体の明るさの差のような、ゆっくり変わる明るさを先に落とす
- 多段: 勾配の強さを2×2の平均で縮め、大きい辺が96px以下になるまで段を作る（640px幅で4段）。最も粗い段で全範囲を探し、局所最大を上位8つまで残して、細かい段ごとに2倍の位置の±2pxで探し直す。同じ位置に集まった候補は一つにまとめる
- 並べ方: 重なった長方形の勾配の正規化相関 r と標本数 n から、`atanh(r)·√(n−3)` を根拠の強さとして並べる。小さい重なりで偶然高い相関が出た候補が、広い重なりの候補を追い越さないようにするため。r も根拠の強さも診断値で、合格線ではない
- 相関の計算: M2 の照合（#318）と同じ関数（平均を引いて正規化した内積）を共有する。写した二つ目の実装は持たない

数値のしきい値を使わない次の検査に一つでも通らなければ `undetermined`（判定不能）を返し、Cの位置を変えない。通れば `estimated-not-judged`（基準による判定なし）として位置を適用する。承認されたしきい値が無い間はこの扱いにする（#364 の仮定。M2_AUTO_OVERLAP.md 14.2 節 Q9 の推奨）。

| 理由コード | 条件 |
|---|---|
| `no-candidate` | 比べられる模様が無く、相関を計算できる位置が一つも無い |
| `tied-candidates` | 最大の候補と同じ強さの候補がある（局所の探索の中を含む） |
| `search-boundary` | 最大の候補が探索範囲の端にある。範囲の外にある本当の位置を端に寄せて出さない |
| `refinement-boundary` | 細かい段で、探し直した窓の端（範囲の端ではない側）に最大が来た。粗い段の山が本物の山を含んでいない |
| `reverse-mismatch` | A/Bを入れ替え、両方を180°回して同じ探索をやり直すと、同じ位置に戻らない。段の区切りと差分の向きが変わるので、標本の取り方に依存した山はここで落ちる |

ログには推定ごとに一行 `C auto_overlap_v2 status=... reason=... orientation=... levels=... candidates=... best_overlap_px=... best_vertical_px=... best_correlation=... best_evidence=... best_samples=... second_overlap_px=... second_vertical_px=... second_evidence=... evidence_gap=... reverse_overlap_px=... reverse_vertical_px=... applied=0|1 quality_accepted=0` を出す（候補が無い欄は省く）。適用した時は、従来の `C auto_translation_proposal=1 overlap_px=... vertical_px=... correlation=... quality_accepted=0` も同じ形で続けて出す。画面は、適用時「自動位置を適用（基準による判定なし・要目視確認）」、判定不能時「自動位置を決められません（理由）。Cの位置は変えていません」。

設計案（5.4 節）のうち、次は I1 に入れていない。事前の位置の近くを先に探すこと（保持値は I2・I8）、比べる標本の数の下限（数値なので所有者決定欄 N1 の扱いと合わせる。代わりに上の根拠の強さで並べる）、続く frame で同じ結果を求めること（回数 N5 が未設定）、タイルの検証と相似（I2）。

`preview_merge_contracts` は次を検査する。既知の平行移動（80×60 と 320×200、Bは明るさを2倍＋20）を v2 が見つけ、往復照合も同じ位置に戻ること。`rotated-180` の吊り下げの人工画像で、回した後の座標で既知の移動量を見つけること。無地は `no-candidate`、範囲の外（重なり95%）の本当の位置は `search-boundary` で適用しないこと。入力の画素を変えないこと。640×427 の負の対照4つ（周辺減光、机の格子のような周期模様、ぼけた床に見立てた別の深さの帯、小さい重なりの位置に置いた似た模様。正解は重なり310px・B上下12px）で、上の段落の推定器が外れること（試験の中で外れた位置を出力する）と、v2 が正しい位置か `undetermined` を返すこと。同じ入力で二回呼んで同じ結果になること。normal と rotated-180 の合成の既存の契約は変えない。人工画像の結果であり、吊り下げリグでの安定性（同じ位置か判定不能になるか）は実機で別に記録する。
