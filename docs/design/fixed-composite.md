## 1. 目的と所有者の決定

今は、ライブの C と書き出す JPEG で合成点が違い、JPEG では撮影ごとにも合成点が変わる。

| | ライブの C | 両台撮影で書き出す JPEG |
|---|---|---|
| 位置 | 平行移動だけ（自動位置合わせ v2 #364 か手動） | C の位置を初期値にして、撮影ごとに相似を推定して当てる（#365） |
| 継ぎ目 | 帯の全体を線形 feather | 画像の内容で、行ごとに曲がる道筋を選ぶ seam-cut（#368） |
| 明るさ | 合わせない | 継ぎ目に沿って B に比を掛ける（#368） |

所有者は 2026-11-04 に次を決めた（#396）。

- ライブの C は書き出す JPEG の合成に合わせ、見え方を同じにする。撮影ごとに合成点（幾何と継ぎ目の位置）を変えない
- Q1 明るさ: 撮影ごとに合わせてよい。#368 と同じく継ぎ目に沿って B に比を掛け、C でも同じ計算をする。合成の位置は動かさない
- Q2 #362: 「設置が変わったら校正をやり直して、固定の位置を更新する」と読み替える。重なりの自動推定は、ずれの検出と再校正の案内にだけ使う
- Q3 ADR-0036: 決定1（C を承認済み profile で描く表示専用の合成）だけ承認。決定2 は保留
- Q4 継ぎ目（同日に 2 回改定。下は最後の決定）: 縦にまっすぐな 1 本。列は基本固定で、設置ごとの固定の合成条件（#399）に持たせ、すべての撮影で同じ列を使う。撮影ごとに自動で列を選ぶことはしない。列は人が決め、C の画面で継ぎ目の線をマウスでドラッグして、重なりの帯の余裕の内側で左右に動かす。C で動かした列が、その後の撮影の JPEG にも使われる。選んだ列は報告に記録し、検品の時に一目で分かるようにする
  - 経緯: 最初は「列は校正の時にずれが最も小さかった位置で決め、校正データに持たせる」、1 回目の改定は「撮影ごとに帯の余裕の中で最も良い列を探してよい」。どちらも最後の決定で置き換わった
- 確認点 A・B・C の回答: B7 以外は案のとおり承認（※所有者は B7 だけを取り上げて直したので、ほかは案のとおりと読んだ）。A（#403 の設計の案 1〜7）は 5 節のとおり。B2 は二状態（`ready-auto-correction` を廃止）。B5 は明るさの比に上限を置く（値は実機で測ってから）。B6 は #385 の D2（局所合わせ）を取り下げる。C1 は「人の操作で決めた列の保存は ADR-0036 決定1 の 5 に当たらない」
- B7（所有者の修正）: ピントは撮影のたびに合わせ直してよく、設置の時に固定する運用にはしない。ピントの合わせ直しや高さの違いで左右のカメラの写る大きさ（倍率）に差が出た時は、差が上限以内なら撮影ごとに倍率だけを補正する。上限を超えたら補正せず、ゲートで不合格にして「ピントか高さを確かめてください」と案内する。回転と平行移動は撮影ごとに直さない。継ぎ目の列は変えない
- B7 の上限: 1% で始める（左右の倍率の差が 1% 以内なら撮影ごとに補正し、超えたら補正せずゲートで不合格・案内）。値は実機で測った後に見直す
- B7 の細部（所有者の言葉「推奨どおりで」）: 回転は固定の値に縛り、撮影ごとに変えるのは倍率だけ。倍率の補正の中心は継ぎ目の列の上に置き、継ぎ目の線を動かさない。倍率を推定できない時は補正せず、固定の写像のまま合成してゲートの判定に任せる

この文書の目標は、上の表を次のようにすることである。

| | ライブの C（#401） | 書き出す JPEG（#400） |
|---|---|---|
| 位置と回転 | 固定の合成条件（#399）を `S` でライブビューの画素へ縮めたもの | 固定の合成条件（#399） |
| 倍率 | 固定のまま（撮影の前に倍率を知らない） | 左右の倍率の差が上限以内なら撮影ごとに補正する（6 節） |
| 継ぎ目 | 固定の合成条件の列（縦一直線）を `S` で縮めたもの。人がここでドラッグして動かせる（#403） | 固定の合成条件の列（縦一直線）。報告に記録する |
| 明るさ | frame ごとに、継ぎ目に沿った A/B の比を B に掛ける | 撮影ごとに、同じ計算 |
| 撮影ごとの推定 | 診断だけ（#402） | 倍率の部分だけを補正に使い、ほかは診断として報告に残す（#400） |

撮影ごとに変わるのは、明るさの比と、JPEG の上限以内の倍率だけ。平行移動・回転・継ぎ目の列は動かない。列が変わるのは、人が C の画面で動かして保存した時だけ。C と JPEG の幾何の違いは、`S` の縮尺を除くと、上限以内の倍率の差だけになる。

## 2. 固定の合成条件（#399）

承認済みの profile が出るまでの開発経路で使う、設置ごとに一度作る合成条件。製品経路では承認済み rig profile が写像の役を持つ（ADR-0036 決定1 の 2）。製品経路で継ぎ目の列と倍率の上限を profile に持たせるかは #45 の時に決める（確認点 C2）。

### 2.1 持つもの（#399 の書式 `a0.fixed-composite-condition.v1`）

#399 で書式と reader・writer を実装した（経路への接続は #400・#401）。欄の正本は [WPD_STILL_REVIEW.md](../WPD_STILL_REVIEW.md) の「設置ごとの固定の合成条件 (#399)」の節で、ここでは設計の要点だけを書く。

| 欄 | 単位・座標 | 備考 |
|---|---|---|
| `approval` | 常に `unapproved` | 承認を表す値は持てない |
| `createdUtc` | UTC（秒） | 作った時刻。有効期限は持たない（決まっていない） |
| `source` | review 報告の SHA-256・`pairId`・`method` | 元にした保存済みの review の報告。`method` は報告の `geometryBasis` と同じ名前。パスは持たない |
| `mountOrientation` | `normal` / `rotated-180` | #361 と同じ値。写像と列は回した後の座標 |
| `sourceDimensions` | 原寸の画素 | 撮影画像の幅と高さ |
| `mapping` | 原寸の画素と度 | B の画像中心の平行移動・回転・倍率と、出力の `crop`。`FixedCompositeRenderParameters` が `PairRenderParameters` を作る |
| `output` | 原寸の画素 | crop 後の合成の大きさ |
| `scaleAutoCorrectionMaxPercent` | % | 撮影ごとに倍率だけ補正してよい差の上限。所有者の決定は 1%（初期値。実機で測った後に見直す）。記録を作る時に方針ファイル（`wpd-merge-policy.json` の同じ名前の欄）から写す。コードの既定値にはしない。未承認 |
| `seam.column`・`seam.origin` | 出力の画素（原寸） | 継ぎ目の列と、その出どころ（`band-center-provisional` か `operator`）。初期値は 2.4 節。人が C の画面で動かす（5 節） |

- 校正（#374）から作る場合の欄は v1 に無い。校正由来の出どころが決まったら、その欄を足した新しい schema 名で足す（v1 の reader は知らない欄を拒否する）
- v1 は最初の記録の書式で、前の記録を指す欄（親の SHA-256）を持たない。改訂の欄と、どの記録を有効にするかは #403 で足す（5 節の 3）
- 倍率の上限を方針ファイルと記録のどちらから読むか（どちらを優先するか）は #400 で決める（※未決）。どちらでも、コードに既定値として埋め込まない

### 2.2 未承認であること

- 承認済みの profile ではない。approved を名乗らず、製品の合成（approved だけを受け付ける。ADR-0033 の 4 節、ADR-0034 の不変条件1）に渡さない
- 読む側は開発経路だけ（今は既定 OFF の `A0_BUILD_WPD_DUAL_PREVIEW` を付けたビルドで作る WpdDualPreview と StillReview）。製品の配布物に入れない
- 記録と画面に「固定の合成条件（未承認）」と出す。報告の品質の三つの false（`productQualityAccepted`・`physicalScaleVerified`・`liveToStillFieldOfViewVerified`）は変えない

### 2.3 作り方と作り直す時

- 設置の時に一度作る。v1 では、保存済みの review の報告（`LoadSavedStillReview` が通るもの）から、その報告が実際に使った幾何（#365 の自動の相似、手動の改訂、ライブの平行移動）を取り出して作る（`MakeFixedCompositeCondition`）。推定から作った条件は、人が見て確かめた上で使ってよい（確認点 B3）
- 校正（#374）から作ることは v1 の対象外。#374 の結果はレンズの歪みと文書面への写像を持ち、v1 の平行移動・回転・倍率では表しきれない。校正から作る条件の写像の形は、新しい schema を足す時に決める（※未決）
- 作るのも直すのも人の明示の操作だけ。撮影の結果から自動で作り直さない
- 写像を作り直すのは設置が変わった時（再校正）だけ。継ぎ目の列は人が C の画面で動かして「この列で固定」を押した時に変わる。どちらも新しい改訂として保存し、前の記録を消さずに残し、新しい記録は前の記録の SHA-256 を持つ（5 節の 3）。v1 の writer は既にあるファイルを上書きしない。改訂の欄とどの記録を有効にするかは #403 で足す
- 壊れた記録、知らない版、欠けた欄は拒否する。既存の報告と方針ファイル（`wpd-merge-policy.json`、`wpd-mount-orientation.json`）の形式は変えない

### 2.4 継ぎ目の列の初期値

- 条件を作った時の列は帯（A と B が両方写る範囲）の中央にする（※仮）。記録と画面に ※仮 と出し、列の出どころを「帯の中央の仮の値」にする
- 人が C の画面で動かして保存した後は、その列を使い、出どころを「人が決めた値」にする

## 3. 縦一直線の継ぎ目の合成（#398）

### 3.1 関数

純粋な関数にする。カメラ・ファイル・時計に依存しない。列は選ばず、入力として受け取る。

- 入力: 向きを当てた A/B、写像（`PairRenderParameters`。JPEG では 6 節の倍率を当てた後の写像）、継ぎ目の列（出力の画素）、設計定数
- 出力: 合成画像と、明るさの比の記録（範囲、飽和で倍率を下げた画素の数）
- 継ぎ目の左は A だけ、右は B だけ。継ぎ目を中心とする混ぜ幅の中だけ B の重みを 0 から 1 へ直線で変える
- 帯の外は `RenderPair` と同じ画素（B の明るさの補正を除く）
- 継ぎ目の列が、どこかの行で A と B の重なりと混ぜ幅から外れる時は、合成せずに失敗にする（#398 の `RenderPairFixedSeam` は例外で止める。合成できるかを先に確かめる `CanRenderFixedSeam` もある）

### 3.2 #368 との共有

#368 の `RenderPairSeamCut`（`src/m2/include/a0/m2/experimental/seam_blend.hpp`）を、道筋を選ぶ部分と、決まった道筋で混ぜる部分に分け、混ぜる部分を共有する。縦一直線の継ぎ目は「すべての行で同じ列の道筋」で、#368 の報告の書き方では `steps` がすべて `0` になる。`RenderPairSeamCut` の出力と既存の試験（`m2_seam_blend_contracts`）は変えない。行ごとに曲がる道筋は、書き出す合成と C には使わない。

### 3.3 明るさ

#368 の「明るさ」と同じ計算にする。

- 各行で、継ぎ目を中心とする窓の A/B の輝度の和を求め、行方向に箱型の和を 2 回取ってから比 A/B を出す
- 比は B に掛ける（A が基準）。継ぎ目で全量、そこから出力の右端へ向けて直線で 1 に戻す
- 3 チャンネルに同じ倍率を掛ける。255 を超えるチャンネルが出る画素は、その画素だけ倍率を下げ、数を記録する
- 比を求めても、写像と継ぎ目の列は動かさない
- 比には上限を置く（確認点 B5）。値は実機で測ってから決める（※未決）。上限を超えた時の扱い（補正せず案内するか、不合格にするか）も値と一緒に決める（※未決）。値が決まるまでは比を記録するだけで、上限で判定しない

### 3.4 設計定数

#368 の `kSeamBlendDesign`（混ぜる幅 8 px、明るさの窓の半幅 32 px、行方向の箱型の半径 128 行）を撮影画像の画素で使う。承認値ではない。

C では同じ定数を `S` で縮めると、混ぜる幅が 1 画素に届かない。C での最小の幅と窓の扱い（縮めた値を切り上げるか、下限を置くか）は #398・#401 で決め、報告と画面の注記に書く（※未決）。この違いがあるので、C と JPEG の画素は縮尺の比で一致しない。#398 の試験が確かめるのは、同じ写像と同じ列を渡した時に幾何（写像と継ぎ目の位置）が縮尺の比で一致すること。

## 4. JPEG の経路（#400）

- 「両台撮影 → 仮Merge保存」の合成の平行移動・回転と継ぎ目の列を、固定の合成条件だけで決める。倍率だけは 6 節のとおり撮影ごとに補正する。合成は 3 節の関数で行う
- #365 の撮影ごとの相似の推定は残す。倍率の部分を 6 節の補正に使い、平行移動と回転は固定の条件からのずれとして報告に書くだけにする
- #368 の内容で選ぶ道筋を、診断として報告に残すかを #400 で決める（合成には使わない）
- 固定の合成条件が無い時は、合成せずに理由を出す。原画像 2 枚の保存は変えない
- 報告は新しい版を足して区別する（版の名前は #400 で決める）。持つもの（※案）: 固定の合成条件の hash と出どころ、使った継ぎ目の列とその出どころ（5 節の 7）、倍率（推定した値、当てた値、上限と出どころ、補正しなかった理由）、明るさの比の範囲、診断（#365 の推定と固定の条件との差）。品質の三つの false と向きの欄は従来どおり。古い版（v1〜v3・v5）の reader は残す
- 完了条件（#400）: 入力の内容を変えても平行移動・回転と継ぎ目の列が同じであること、倍率の差が上限以内の時だけ倍率が当たることを試験で確かめる
- StillReview の手動の再 Merge（#336・#338）は、保存済みの組を調べる道具として残す（確認点 B9）。StillReview で列を変えて作り直す場合の扱いは 5 節の 6

## 5. 継ぎ目の列を決める操作と保存（#403、決定 2026-11-04、#396）

C の画面で縦一直線の継ぎ目の線をマウスでドラッグして左右に動かし、決めた列を固定の合成条件（#399）に保存する。以後の撮影では JPEG と C の両方がその列を使う。合成の関数（#398）は列を入力に取る。所有者は確認点 A の案 1〜7 を承認した（※B7 以外は案のとおりと読んだ）。

### 5.1 前提（#396 の Q4 の最後の決定）

- 継ぎ目は縦にまっすぐな 1 本。行ごとに曲がる道筋は不可
- 列は基本固定。すべての撮影で同じ列を使う。撮影ごとに自動で列を選ぶことはしない
- 列は人が決める。写像（幾何）は撮影ごとに変えない（倍率の例外は 6 節。列は動かさない）
- 選んだ列は報告に記録し、検品の時に一目で分かるようにする

### 5.2 決定（確認点 A の 1〜7）

1. **ドラッグできる範囲**: 継ぎ目の列と混ぜ幅の半分が、すべての行で A と B の両方が写る範囲に入る列だけ。範囲の外へは動かない
2. **保存する列**: 原寸の列。C の画面の画素は縮尺で原寸に直し、丸めた列を保存する。C では保存した列を縮めて描く
3. **保存の仕方**: 列を動かして「この列で固定」を押した時だけ、固定の合成条件を新しい改訂として保存する。前の記録は消さずに残し、新しい記録は前の記録の SHA-256 を持つ。ドラッグしただけでは保存しない。#399 の v1 は最初の記録の書式で親の欄を持たないので、親の欄とどの記録を有効にするかは #403 で書式に足す
4. **自動で良い列の候補を出す処理**: 最初は作らない。必要になったら、候補を表示するだけの別の Issue にする
5. **白い紙だけの列**: 継ぎ目は目立たないが、ゲート（#385 の Q3）が確かめられない。選ぶこと自体は止めず、画面に「この列は確かめられる模様がありません」と出す
6. **保存済みの結果（StillReview）で列を変えて作り直す時**: 今の手動の改訂と同じく、親を残した別保存にする
7. **見せ方**: C と StillReview に継ぎ目の縦線を表示する（表示の入切ができる）。報告には列と、その出どころ（帯の中央の仮の値か、人が決めた値か）を書く

### 5.3 実装で決める細部

- 丸めの方法（四捨五入か切り捨てか）と、C で 1 画素動かした時に原寸で何列動くか（`S` に依存する）
- 1 の範囲を、縮めた C の上でどう示すか。明るさの窓が帯の外に出ないための余裕との関係（#394 の 2 で、#368 の端の余裕がゲートの inset より狭いことが分かっている）
- 5 の「模様が無い」の判定の方法（ゲートの区画の分類を使うか）
- 6 の別保存の報告で、列を変えた改訂を固定の合成条件に戻す操作を設けるか（今の決定には無い。設けない場合、固定の合成条件を変えるのは C の画面の操作だけ）
- 報告の欄の名前と形

## 6. 倍率の撮影ごとの補正（B7、#400）

- ピントは撮影のたびに合わせ直してよい（AF-S、#385 の D3）。設置の時に固定する運用にはしない
- 左右の倍率の差が上限以内なら、撮影ごとに B に倍率だけを当てる。上限を超えたら補正せず（倍率 1）、ゲートで不合格にして「ピントか高さを確かめてください」と案内する。上限で切った部分的な補正はしない
- 上限は所有者の決定で 1%（初期値。実機で測った後に見直す前提）。倍率の差は「倍率を % にした値と 100 の差の絶対値」で比べ、1% ちょうどは補正する（#365 の倍率の判定と同じ比べ方、※案）
- 値はコードに既定値として埋め込まない。方針ファイル（`wpd-merge-policy.json` の `scaleAutoCorrectionMaxPercent`）か固定の合成条件の記録（2.1 節）から読む。どちらにも値が無ければ倍率を補正しない
- 所有者の決定（2026-11-04、#396）: 回転は固定の値に縛り、撮影ごとに変えるのは倍率だけ。実装（#400）: #365 の推定器（`EstimateOverlapSimilarity`）が返した合意タイルから、回転を固定の写像に縛り、平行移動は推定の中だけ自由にした最小二乗で倍率を求める（`DecideFixedScale`）。当てるのは倍率だけで、倍率で説明できなかったずれは報告の `unexplainedShift` に診断として残す。推定器自身の相似の値も診断に回す
- 所有者の決定（2026-11-04、#396）: 補正の中心は継ぎ目の列上の点（出力の窓の縦の中央）にし、継ぎ目の線を動かさない（`FixedScaleCenter`）。ピントや高さの倍率は B の光学中心のまわりにかかるので、中心を B の画像の中心（固定の写像で移した点）にするかを所有者に確認中（※要確認。中心を変えても継ぎ目の列は動かない）
- 所有者の決定（2026-11-04、#396）: 推定できない時（繰り返し模様、候補が定まらないなど）は補正せず、固定の写像のまま合成し、ゲートの判定に任せる。報告に「倍率を推定できなかった」理由を残す
- 推定した倍率、当てた倍率、上限の値と出どころ、補正しなかった理由を報告に記録する。当てた倍率は次の撮影に持ち越さない
- ライブの C は撮影の前に倍率を知らないので、固定の写像のまま描く。C と JPEG の幾何の違いは、上限以内の倍率の差だけになる

## 7. C の経路（#401）

- 固定の合成条件の写像と列を `S` でライブビューの画素へ縮め、3 節の関数で描く。明るさの比も frame ごとに同じ計算をする。倍率は補正しない（6 節）
- `S` はライブビューの画素と撮影画像の画素の対応（拡縮と平行移動）。今の仮定は「ライブビューの frame が撮影画像の全体を、縦横それぞれの比で縮めて写す」（#334 の正規化の式と同じ）。実機で測るまで（#309）この仮定のままにし、画面と文書に ※未検証 と書く。`S` が違っていると、C で合わせた列が JPEG の別の場所に来るので、列のドラッグの結果も ※未検証 の仮定に乗る
- C の手動の位置合わせと自動位置合わせ v2 は、C の位置を変えない（表示の変更は #402）。継ぎ目の線のドラッグ（5 節）は列だけを変え、写像は変えない
- C は表示専用で、保存しない。撮影・保存の合成・補正の推定・profile の入力にしない（ADR-0036 決定1 の 5）。C の画面で人が動かした列を固定の合成条件に保存するのは、ライブビューの画素から推定した値ではなく人の操作で決めた値なので、この規則に当たらない（確認点 C1）
- 製品の C は、承認済みの profile が出るまで操作者の画面に出さない（ADR-0036 決定1 の 7）。この節の C は開発経路の C
- 完了条件（#401）: 同じ固定の条件から、縮めた C と原寸の JPEG（倍率を当てない場合）の幾何が縮尺の比で一致することを試験で確かめる

## 8. 自動推定の役目（#402）

- 自動位置合わせ v2（#364）は C の位置を変えない。固定の合成条件とのずれ（平行移動。相似にするかは #402 で決める）を表示する
- ずれが大きい時に「校正し直してください」と案内する。案内の境目は所有者の決定待ちで、決まるまでは値を表示するだけにする（確認点 B4）
- 撮影時の相似の推定（#365）は、倍率の部分だけを 6 節の補正に使い、ほかは診断として報告に残す
- 推定の結果で固定の合成条件を自動で作り直さない。写像を作り直すのは 2.3 節の人の操作、列を動かすのは 5 節の人の操作だけ
- 設置の判定は `ready` と `physical-adjustment-required` の二状態にする（確認点 B2、`ready-auto-correction` は廃止）。ずれの大きさは状態にせず、診断の値として出す。`SetupReadiness`（`src/m2/include/a0/m2/setup_assessment.hpp`）の変更は別の Issue で行う（※未着手）

## 9. ゲート（#385）との関係

- 所有者の決定（#385、2026-11-04）: 合格線（出力 1 px 以下）を保証する範囲を、重なりの帯の全域から「固定した継ぎ目の列 ± 混ぜる幅＋余裕」に改める。継ぎ目から離れた所は片方のカメラの画素だけを使うので、出力では二重にならない
- 帯の全域のずれは、校正の良し悪しを見る診断として残し、合否には使わない。余裕の幅は設計で決める（※未決）。ゲートの実装と [品質ゲート](../M2_SEAM_QUALITY_GATE.md) の本文の書き換えは #404 で行う

- ゲートは、書き出す合成と同じ写像で A と B を別々に置いて測る（[品質ゲート](../M2_SEAM_QUALITY_GATE.md) の 3.2 節）。写像が固定になっても作りは変わらない。倍率を当てた撮影は、当てた後の写像で測る
- 遷移帯は、固定の合成条件の列と混ぜ幅から決まる。`SeamCutTransitionBand` に、すべての行で同じ列の道筋を渡せる
- 倍率の差が上限を超えた撮影は、補正せずにゲートで不合格にし、「ピントか高さを確かめてください」と案内する（6 節）
- 撮影ごとに位置と回転を直さないので、台の揺れやシャッターの振動で組ごとに A と B が動いた撮影は、固定の写像からずれた分がゲートで測られ、合格線を超えれば書き出されない（原画像は残す、確認点 B1）。揺れない取り付けが前提になる。#385 に記録した吊り下げのままの実機では、場面を動かさなくても継ぎ目のずれが組ごとに揃って動き、一部の組で B がぶれた。固定の写像では、この動きのうち倍率で説明できない分がそのままゲートのずれに出る（※推定。固定の写像での実機の確認は無い）
- 局所合わせ（#385 の D2）は取り下げた（確認点 B6）。品質ゲートの 5.6 節に追記を置いた

## 10. #394・WP-04 への影響

細部は再開時に見直す。今わかっている点だけを書く。

- #394 の 1（実写で大域の確認の錨が取れない）: 固定の写像になっても、ゲートが錨で配置を確かめることは変わらない。ただし、撮影ごとの推定が周期 1 つ分ずれた位置を合成に使う危険は無くなる。配置の確認は、固定の条件を作る時に一度行う確認へ役目を移せる（※案）。6 節の倍率の推定は繰り返し模様で誤ることがあり、推定できない時は補正しない（※案）

- #394 の 4（局所合わせの前提）: D2 を取り下げたので、この項目は不要になる見込み（#394 の再開時に確かめる）
