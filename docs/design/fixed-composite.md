# 固定の合成条件と縦一直線の継ぎ目による合成 — 設計（Issue #397）

状態: 設計。方針は所有者の決定（#396、2026-11-04。Q4 は同日に改定）。規則は `docs/DECISIONS.md` の ADR-0036 決定1（Accepted）と ADR-0037（Proposed）。実装は #398〜#403 で行い、この文書の時点ではどれも未実装。継ぎ目の列の選び方（#403）は未決で、設計を所有者に見せてから実装する
対象 Issue: #397。親: #396。実装: #398（縦一直線の継ぎ目の合成関数。列を入力に取る）、#399（固定の合成条件）、#400（JPEG の経路）、#401（C の経路）、#402（自動推定を診断と再校正の案内に）、#403（撮影ごとに継ぎ目の列を選ぶ）。その後: #394 → WP-04
範囲外: 値の決定（再校正の案内の境目、明るさの比の上限、ずれの目標）、色の補正（#46）、承認済み profile の発行（#45）、ライブビューの 3 命令の例外（ADR-0036 決定2、保留）
公開範囲: 実画像、実測の値、機体の識別子、ファイルの場所は書かない

## 1. 目的と所有者の決定

今は、ライブの C と書き出す JPEG で合成点が違い、JPEG では撮影ごとにも幾何が変わる。

| | ライブの C | 両台撮影で書き出す JPEG |
|---|---|---|
| 位置 | 平行移動だけ（自動位置合わせ v2 #364 か手動） | C の位置を初期値にして、撮影ごとに相似を推定して当てる（#365） |
| 継ぎ目 | 帯の全体を線形 feather | 画像の内容で、行ごとに曲がる道筋を選ぶ seam-cut（#368） |
| 明るさ | 合わせない | 継ぎ目に沿って B に比を掛ける（#368） |

所有者は 2026-11-04 に次を決めた（#396）。

- ライブの C は書き出す JPEG の合成に合わせ、見え方を同じにする。撮影ごとに写像（幾何）を変えない
- Q1 明るさ: 撮影ごとに合わせてよい。#368 と同じく継ぎ目に沿って B に比を掛け、C でも同じ計算をする。合成の位置は動かさない
- Q2 #362: 「設置が変わったら校正をやり直して、固定の位置を更新する」と読み替える。重なりの自動推定は、ずれの検出と再校正の案内にだけ使う
- Q3 ADR-0036: 決定1（C を承認済み profile で描く表示専用の合成）だけ承認。決定2 は保留
- Q4 継ぎ目（同日に改定）: 縦にまっすぐな 1 本。最初の決定は「列は校正で決めて校正データに持たせる」だったが、改定で、撮影ごとに重なりの帯の余裕の中で最も良い列を探してよいことになった。行ごとに曲がる道筋（#368 の seam-cut の形）は不可で、検品の時にどこで合成したかを追わないと分からない形は認めない。選んだ列は報告に記録し、検品の時に一目で分かるようにする

この文書の目標は、上の表を次のようにすることである。

| | ライブの C（#401） | 書き出す JPEG（#400） |
|---|---|---|
| 位置 | 固定の合成条件（#399）を `S` でライブビューの画素へ縮めたもの | 固定の合成条件（#399） |
| 継ぎ目 | 縦一直線の 1 本。列は #403 の規則で選ぶ（※未決） | 縦一直線の 1 本。列は #403 の規則で選び、報告に記録する（※未決） |
| 明るさ | frame ごとに、継ぎ目に沿った A/B の比を B に掛ける | 撮影ごとに、同じ計算 |
| 撮影ごとの推定 | 診断だけ（#402） | 診断だけ。報告に残す（#400） |

撮影ごとに変わってよいのは、継ぎ目の列と明るさの比だけ。どちらも写像を動かさない。

## 2. 固定の合成条件（#399）

承認済みの profile が出るまでの開発経路で使う、設置ごとに一度作る合成条件。製品経路では承認済み rig profile が同じ役を持つ（ADR-0036 決定1 の 2）。継ぎ目の列は持たない（列は撮影ごとに選ぶ、5 節）。

### 2.1 持つもの

| 欄 | 単位・座標 | 備考 |
|---|---|---|
| 写像 B→A | 撮影画像の画素（向きを当てた後） | 今の `PairRenderParameters::camera_b_to_camera_a` と同じ 3×3。相似で作った場合も 3×3 で持つ |
| 取り付けの向き | `normal` / `rotated-180` | #361 と同じ値。写像は回した後の座標 |
| 出どころ | 推定（#364・#365）か校正（#374） | 推定の時は推定器の id、校正の時は校正の記録の hash を持つ（※案） |
| 作った時刻 | UTC | 有効期限は持たない（決まっていない） |

出力の範囲（crop）と撮影画像の寸法を欄にするかは #399 で決める（※未決）。

### 2.2 未承認であること

- 承認済みの profile ではない。approved を名乗らず、製品の合成（approved だけを受け付ける。ADR-0033 の 4 節、ADR-0034 の不変条件1）に渡さない
- 読む側は開発経路だけ（今は既定 OFF の `A0_BUILD_WPD_DUAL_PREVIEW` を付けたビルドで作る WpdDualPreview と StillReview）。製品の配布物に入れない
- 記録と画面に「固定の合成条件（未承認）」と出す。報告の品質の三つの false（`productQualityAccepted`・`physicalScaleVerified`・`liveToStillFieldOfViewVerified`）は変えない

### 2.3 作り方と作り直す時

- 設置の時に一度作る。元は、設置時の推定（#364 のライブの推定、#365 の撮影 JPEG での相似）か、校正（#374）の結果
- 校正から作る場合、#374 の結果はレンズの歪みと文書面への写像を持ち、3×3 の B→A では表しきれない。校正から作る条件の写像の形（3×3 で近似するか、profile 2.0.0 と同じ文書平面基準の形を持つか）は #399 で決める（※未決）
- 作るのは人の明示の操作だけ。撮影の結果から自動で作り直さない
- 作り直すのは設置が変わった時（再校正）だけ。作り直したら新しい記録にし、前の記録を書き換えない（ADR-0037 の不変条件3、※案）
- 壊れた記録、知らない版、欠けた欄は拒否する。既存の報告と方針ファイル（`wpd-merge-policy.json`、`wpd-mount-orientation.json`）は変えない

## 3. 縦一直線の継ぎ目の合成（#398）

### 3.1 関数

純粋な関数にする。カメラ・ファイル・時計に依存しない。列は選ばず、入力として受け取る（選ぶのは #403）。

- 入力: 向きを当てた A/B、写像（`PairRenderParameters`）、継ぎ目の列（出力の画素）、設計定数
- 出力: 合成画像と、明るさの比の記録（範囲、飽和で倍率を下げた画素の数）
- 継ぎ目の左は A だけ、右は B だけ。継ぎ目を中心とする混ぜ幅の中だけ B の重みを 0 から 1 へ直線で変える
- 帯の外は `RenderPair` と同じ画素（B の明るさの補正を除く）
- 継ぎ目の列が、どこかの行で A と B の重なりと混ぜ幅から外れる時は、合成せずに失敗を返す。外れた最初の行を返す

### 3.2 #368 との共有

#368 の `RenderPairSeamCut`（`src/m2/include/a0/m2/experimental/seam_blend.hpp`）を、道筋を選ぶ部分と、決まった道筋で混ぜる部分に分け、混ぜる部分を共有する。縦一直線の継ぎ目は「すべての行で同じ列の道筋」で、#368 の報告の書き方では `steps` がすべて `0` になる。`RenderPairSeamCut` の出力と既存の試験（`m2_seam_blend_contracts`）は変えない。行ごとに曲がる道筋は、書き出す合成と C には使わない。

### 3.3 明るさ

#368 の「明るさ」と同じ計算にする。

- 各行で、継ぎ目を中心とする窓の A/B の輝度の和を求め、行方向に箱型の和を 2 回取ってから比 A/B を出す
- 比は B に掛ける（A が基準）。継ぎ目で全量、そこから出力の右端へ向けて直線で 1 に戻す
- 3 チャンネルに同じ倍率を掛ける。255 を超えるチャンネルが出る画素は、その画素だけ倍率を下げ、数を記録する
- 比を求めても、写像と継ぎ目の列は動かさない

### 3.4 設計定数

#368 の `kSeamBlendDesign`（混ぜる幅 8 px、明るさの窓の半幅 32 px、行方向の箱型の半径 128 行）を撮影画像の画素で使う。承認値ではない。

C では同じ定数を `S` で縮めると、混ぜる幅が 1 画素に届かない。C での最小の幅と窓の扱い（縮めた値を切り上げるか、下限を置くか）は #398・#401 で決め、報告と画面の注記に書く（※未決）。この違いがあるので、C と JPEG の画素は縮尺の比で一致しない。#398 の試験が確かめるのは、同じ写像と同じ列を渡した時に幾何（写像と継ぎ目の位置）が縮尺の比で一致すること。

## 4. JPEG の経路（#400）

- 「両台撮影 → 仮Merge保存」の合成の幾何を、固定の合成条件だけで決める。合成は 3 節の関数で行い、列は #403 の規則で選ぶ
- #365 の撮影ごとの相似の推定は残し、固定の条件からのずれとして報告に書く。合成には当てない
- #368 の内容で選ぶ道筋を、診断として報告に残すかを #400 で決める（合成には使わない）
- 固定の合成条件が無い時は、合成せずに理由を出す。原画像 2 枚の保存は変えない
- 報告は新しい版を足して区別する（版の名前は #400 で決める）。持つもの（※案）: 固定の合成条件の hash と出どころ、選んだ継ぎ目の列（欄の形は #403）、明るさの比の範囲、診断（#365 の推定と固定の条件との差）。品質の三つの false と向きの欄は従来どおり。古い版（v1〜v3・v5）の reader は残す
- 完了条件（#400）: 入力の内容を変えても写像が同じであることを試験で確かめる
- StillReview の手動の再 Merge（#336・#338）は保存済みの組を調べる道具として今は変えない。残すかは所有者の確認事項（ADR-0037 の確認事項 10）

## 5. 継ぎ目の列の選び方（#403、未決）

撮影ごとに、重なりの帯の余裕の中で、縦一直線の継ぎ目を置く列を選ぶ。合成の関数（#398）は列を入力に取り、選ぶのは #403。**設計を所有者に見せてから実装する。** この節は決まっていることと未決の項目を並べるだけで、選び方を決めていない。

### 5.1 決まっていること（#396 の Q4 の改定、#403）

- 継ぎ目は縦にまっすぐな 1 本。行ごとに曲がる道筋は不可
- 列は撮影ごとに帯の中で選んでよい。写像（幾何）は撮影ごとに変えない
- 選んだ列は報告に記録し、検品の時に一目で分かるようにする（StillReview の継ぎ目の表示など）

### 5.2 設計で決めること（#403 の案。どれも未決）

| 項目 | #403 に書かれた案 | 未決の点 |
|---|---|---|
| 列の選び方 | ゲート（#385）と同じ量で列ごとのずれを測り、最大が最も小さい列を選ぶ | 量の定義と測る点の置き方。同点の時の決め方（帯の中央に近い方など）。選ぶのに使ったずれを同じ撮影のゲートが判定することになる点をどう扱うか（選び方と判定の独立性） |
| 帯の端からの余裕 | 混ぜ幅と、ゲートの帯の inset（`RequiredBandInsetPx`）と同じ考え方 | 余裕の値と、明るさの窓が帯の外に出ないための余裕との関係。#394 の 2 で、#368 の端の余裕がゲートの inset より狭いことが分かっている |
| 白い紙だけの列 | 継ぎ目としては目立たないが、#385 の Q3（予測の無い白い区画は不合格）のためゲートで確かめられない | 選ぶ時に避けるか、選んでもゲートで不合格になるのを許すか |
| C との関係 | C も同じ規則で列を選ぶ | 撮影の時に C で選んでいた列を JPEG に引き継ぐか、原寸で選び直すか。引き継がない場合、C と JPEG の継ぎ目の位置が違いうる |
| 計算の時間 | C は frame ごと、JPEG は撮影ごと | C で毎 frame 選ぶか、間隔を空けるか。JPEG で両台撮影の 180 秒の期限に収まるか |
| 報告と見せ方 | 報告の欄と、StillReview での見せ方 | 欄の名前と形。StillReview の「継ぎ目を表示」（#368）を縦一直線の列にも使うか |

## 6. C の経路（#401）

- 固定の合成条件を `S` でライブビューの画素へ縮め、3 節の関数で描く。明るさの比も frame ごとに同じ計算をする。列は #403 の規則で選ぶ（※未決）
- `S` はライブビューの画素と撮影画像の画素の対応（拡縮と平行移動）。今の仮定は「ライブビューの frame が撮影画像の全体を、縦横それぞれの比で縮めて写す」（#334 の正規化の式と同じ）。実機で測るまで（#309）この仮定のままにし、画面と文書に ※未検証 と書く
- C の手動の位置合わせと自動位置合わせ v2 は、C の位置を変えない（表示の変更は #402）
- C は表示専用で、保存しない。撮影・保存の合成・補正の推定・条件や profile の入力にしない（ADR-0036 決定1 の 5）
- 製品の C は、承認済みの profile が出るまで操作者の画面に出さない（ADR-0036 決定1 の 7）。この節の C は開発経路の C
- 完了条件（#401）: 同じ固定の条件と同じ列から、縮めた C と原寸の JPEG の幾何が縮尺の比で一致することを試験で確かめる

## 7. 自動推定の役目（#402）

- 自動位置合わせ v2（#364）は C の位置を変えない。固定の合成条件とのずれ（平行移動。相似にするかは #402 で決める）を表示する
- ずれが大きい時に「校正し直してください」と案内する。案内の境目は所有者の決定待ちで、決まるまでは値を表示するだけにする（※仮）
- 撮影時の相似の推定（#365）も、診断として報告に残すだけにする（4 節）
- 推定の結果で固定の合成条件を自動で作り直さない。作り直すのは 2.3 節の人の操作だけ

## 8. ゲート（#385）との関係

- ゲートは、書き出す合成と同じ写像で A と B を別々に置いて測る（[品質ゲート](../M2_SEAM_QUALITY_GATE.md) の 3.2 節）。写像が固定になっても作りは変わらない。写像の関数に固定の条件を渡すだけになる
- 遷移帯は、その撮影で選んだ列と混ぜ幅から決まる。`SeamCutTransitionBand` に、すべての行で同じ列の道筋を渡せる
- 撮影ごとに位置を直さないので、台の揺れやシャッターの振動で組ごとに A と B が動いた撮影は、固定の写像からずれた分がゲートで測られ、合格線を超えれば書き出されない（原画像は残す）。揺れない取り付けが前提になる。#385 に記録した吊り下げのままの実機では、場面を動かさなくても継ぎ目のずれが組ごとに揃って動き、一部の組で B がぶれた。固定の写像では、この動きがそのままゲートのずれに出る（※推定。固定の写像での実機の確認は無い）。列を撮影ごとに選べても、帯の全体が同じ向きに動いた分は消えない
- AF（#385 の D3）で撮影ごとに変わる倍率は、これまで撮影ごとの相似で消す前提だった。固定の写像では残差としてゲートに出る。扱いは所有者の確認事項（ADR-0037 の確認事項 8）
- 局所合わせ（#385 の D2）は撮影ごとに写像を変えるので、#396 の決定と食い違う。扱いは所有者の確認事項（ADR-0037 の確認事項 7）

## 9. #394・WP-04 への影響

細部は再開時に見直す。今わかっている点だけを書く。

- #394 の 1（実写で大域の確認の錨が取れない）: 固定の写像になっても、ゲートが錨で配置を確かめることは変わらない。ただし、撮影ごとの推定が周期 1 つ分ずれた位置を合成に使う危険は無くなる。配置の確認は、固定の条件を作る時に一度行う確認へ役目を移せる（※案）
- #394 の 2（遷移帯の上下の端と横の余裕）: 縦一直線の継ぎ目もすべての行に置くので、上下の端の問題は残る。横の余裕は #403 の帯の端の余裕で扱う
- #394 の 3（広い周期と予測）: 変わらない
- #394 の 4（局所合わせの前提）: D2 の扱いが決まるまで保留
- WP-04（ゲートを開発用プレビューと StillReview につなぐ、「原画像は保存済み、合成だけ失敗」の出し分け）: 開発経路の写像が固定の条件になるので、ゲートに渡す写像が一つに決まり、遷移帯も縦 1 本の帯になる。「固定の合成条件が無い」も「合成だけ失敗」の理由に加わる
