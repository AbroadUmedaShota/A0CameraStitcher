# 固定写像patch照合の細探索（#323）

ローカル検証時追記: [#324で明示job v2による保存JPEG評価CLIへの接続](M2_REFINEMENT_EVAL.md)を追加した。以下は#323で実装したpure計算部の契約・当時の確認範囲。

保存画像の位置合わせで、粗探索の文書mm格子より細かいズレを扱う開発用pure計算部。既存の`EstimateImagePatchCorrection`と`EstimateAutoImagePatchCorrection`に、全引数必須の`PatchRefinementPolicy`を追加したoverloadを用意する。既存overloadは粗探索だけを行い、CLIのjob v1、report、manifest v1/v2/v3の契約は変更しない。今回の細探索はCLI・製品adapter・アプリへ接続していない。

## 処理と拒否条件

1. [既存の粗探索](M2_IMAGE_PATCH_CORRECTION.md)を実行する。contrast、NCC下限、最大と次点との差、探索外周、全候補の被覆をすべて検査し、拒否を細探索で救済しない。
2. 粗探索の最大位置を中心に、間隔を半分にした3×3候補をすべて評価する。明示した段数だけ、最大位置へ中心を移しながら間隔を半減する。段数は1〜8。1段目の間隔は`search_step_mm/2`、最終段は`search_step_mm/2^levels`。この間隔は推定精度の保証ではない。
3. 各候補を固定投影で**元BGR画像**からbilinear samplingする。source patch、平均除去、NCC計算は粗探索と同じ。contrast不足候補は数を記録し、NCC下限と**厳密に一意な最大値**を各段で要求する。粗探索の次点差下限は粗い格子での曖昧性検査として維持する。細かい格子に同じ差下限を流用しない。同点を探索順で成功にしない。局所的な曲線近似やepsilon、scoreのclampは使わない。
4. 細探索も全候補の文書domain・raw被覆を要求する。元の粗探索windowから出る候補、有限でない座標、浮動小数点で候補位置が重複する格子は拒否する。端を切り詰めた探索を成功にしない。細探索の移動総量は軸ごとに粗い間隔未満なので、粗探索で内側のpeakが選ばれていれば、数学上は元window内に収まる。
5. forwardの最終細探索位置からreverseにも同じ粗探索・細探索を行い、元seedとの往復誤差を既存の明示上限で検査する。全seed必須で、外れ点削除や再選定は行わない。自動seed選定の既存被覆余裕（Aは探索幅の2倍、Bは1倍）もこのwindowを含む。
6. 両方向成立後だけ最終位置をraw対応へ変換し、既存のraw逆変換・上限つき相似補正へ渡す。A、K、5歪み、固定profileは変更しない。Bの一時的な`H*T`を使い、最終描画は元画像から一度だけsamplingする。

`PatchSearchResult`の位置、score、標準偏差、候補数は従来どおり粗探索の診断。追加の`refinement`列に段ごとの間隔・結果・位置・最大/次点score・最大target標準偏差・候補数を保存する。`outcome`は細探索も含む照合全体の結果で、拒否時の候補位置を利用可能な対応と解釈しない。usableなraw対応は両方向・往復検査後の`correspondence`だけ。

仕事量は`seed数 * 2方向 * patch side² * (coarse search side² + 9*levels)`で上から見積もり、既存の16,000,000 sample評価を超えたら探索前に拒否する。source patch読取りは別に各方向1回以内。新しいファイルI/O、JPEG依存、OpenCV依存、機器操作は追加しない。

## 検証

`m2_image_patch_refinement_contracts`はproductionのsampler/投影を使わず、連続三角関数の模様を二枚へ直接samplingする独立生成器を使う。既知の端数平行移動、正負の微小な回転・倍率差、粗探索だけの負対照、描画の両layout/両kernel、反復決定性、原本不変を検査する。試験の許容差・policyは人工入力用で、承認済み光学条件ではない。

既存処理で`(+2.35,-1.65)` raw画素のズレを与えた再現では、対応点誤差の最大0.738241画素により、0.12画素以内のテストが失敗した。7段の細探索を指定すると最大0.0250488画素。最終描画の平均絶対差は未補正7.44〜7.54 DNから0.132〜0.185 DNへ減少した。小さな回転・倍率差を併用した二例の対応点誤差は最大0.0451778画素以内。

ローカル検証時: MSVC x64、SDKなし。新規329チェックはRelease/Debugとも成功。関連CTestは両構成11/11成功。既存保存JPEG CLIの5,118チェックとschemaの236チェックも両構成成功し、既存43成果物は変更前/後・構成間でbyte一致した。[当日の開発状況](DEVELOPMENT_STATUS_20261016.md)を参照。

これらはdecoded合成bufferでの結果。一般の模様、JPEG圧縮、実写、レンズの光学品質、最終seam、任意の回転/倍率差に対する精度・頑健性は保証しない。patch自体の回転/倍率探索、自由H、profileの自動更新は追加していない。製品の承認profile閾値との対応、CLIの版管理を伴う明示設定・全診断保存、保存JPEGの端数ズレ評価は後続。
